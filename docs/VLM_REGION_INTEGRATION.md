# 부위별 VLM 프로그램 연결

2026-09-16. `UI_HANDOFF.md` §0의 백엔드 추론 경로만 변경했다. §2.2/§9를 확인했고, 카메라 획득·왜곡 보정·로봇 좌표·UI 레이아웃은 변경하지 않았다. 기존 테스트의 기대값 변경도 없다.

## 선택된 모델

`configs/vlm/backend.json`이 있으면 기존 비동기 VLM 작업자가 `region_2b`를 사용한다. 파일이 없는 기존 설치는 종전 Qwen 4B 경로를 유지한다. 설정이 잘못됐거나 가중치 해시가 다르면 자동 우회하지 않고 실패한다.

- Qwen3.5-2B, 고정 revision `15852e8c16360a2fea060d615a32b45270f8a8fc`
- 부위별 학습 후 확인 불가 사례를 추가 학습한 LoRA
- `models/vlm-region-abstain-v1`에 별도 복사. 이전 모델은 보존
- 모델과 토크나이저·어댑터 파일 목록/SHA256 검증 후 GPU 로드
- 현장 검증 완료 모델이 아니다. 결과는 항상 보조 정보이며 `needs_review=true`를 보수적으로 반환한다. 이 값은 기존 OK/NG 판정을 변경하지 않는다.

## 입력과 결과

저장된 스냅샷을 ID·해시로 확인한 다음 `known_defects`의 NG04/NG05 후보를 사용한다. 물체 로컬 좌표와 원본 좌표가 crop translation과 정확히 일치해야 한다. resized/alignment/좌표 변환이 다른 스냅샷은 명시적으로 거절한다. 새 왜곡 보정이나 캘리브레이션 변환은 수행하지 않는다.

각 후보를 가로·세로 각각 25%씩 넓히되 저장된 물체 영역 안으로 제한한다. 점수순 최대 세 후보를 직렬 분석한다. 질문은 NG04 접합부, NG05 구멍 질문이며 후보 코드·점수·정답은 모델 입력에 포함하지 않는다. 결과의 NG04/NG05 접두어는 검출 후보 연결용이며 최종 판정이 아니다. 모델 내부 출력은 observation 하나이고, 백엔드가 기존 결과 스키마로 포장한다.

후보 없음·지원 범위 밖은 정상 판정으로 바꾸지 않는다. 처리 한도를 넘거나 지원하지 않는 후보가 있으면 누락 사실을 설명에 명시한다. 새 모델은 한국어 관찰 문장만 학습했다. generation language=en 요청은 영어로 미지원 안내를 반환하며 자동 번역이나 기존 모델로 우회하지 않는다. UI 표시 언어 변경 기능과는 별개다.

기존 큐의 OFF·취소·시간 제한·결과 토큰 검증·스냅샷/물체 결합·GPU 우선순위를 그대로 사용한다. 기존 VLM 결과는 덮어쓰지 않는다. 새 설정은 다음 모델 작업자 시작 시 읽힌다. 이미 실행 중인 프로그램은 재시작 후 새 VLM 요청을 생성해야 한다. VLM이 OFF이면 자동으로 켜지지 않는다.

## 검증

- 신규 좌표/스냅샷/응답 검증과 기존 VLM·최적화·실시간 뷰포트 테스트 43개 통과.
- 인계 문서 §9의 원본 PC 자산이 필요한 photo/manual 및 station UI 테스트 32개 통과.
- 실제 저장사진 3장(OK/NG04/NG05)과 이전 실제 DETR 검출 기록을 스냅샷으로 구성해 GPU 추론 확인. 이번 점검에서 DETR을 다시 실행한 것은 아니다.
- 실제 비동기 `AnalysisWorker`에서 GPU 작업 3건 완료. 기존 결과 스키마, 객체 ID/스냅샷 해시 결합, 보조 결과 플래그, 새 프롬프트 버전 및 스냅샷 불변 확인.
- 새 코드가 실제 촬영, 로봇 이동, 720×720 새 보정점을 검증한 것은 아니다. 해당 작업은 별도이며 기존 `require` 가드는 유지했다.
