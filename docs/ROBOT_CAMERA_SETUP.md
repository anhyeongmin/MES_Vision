> 2026-09-09 최신 상태: 기본 실행 파일과 검사 시작을 새 전체·상세 회차 실행기에 연결했다. 저장된 전체사진·선택 물체의 상세사진·기본 이유·VLM 설명 화면, 촬영 저장 프로세스 감시, 로봇 운전 프로필, 새 회차 목록과 백업/복원도 연결했다. **선택적 OK·NG 분류 이송까지 연결했다. 새 회차의 기존 검색·CSV·수동 검토·보존 정책도 통합했다.** 실제 장비를 구동해 검증하지 않았다. 분류 사용법은 [STATION_SORTING.md](STATION_SORTING.md), 이력·보관 사용법은 [STATION_HISTORY.md](STATION_HISTORY.md)를 참고한다. 현행 사용법과 범위는 [STATION_OPERATION.md](STATION_OPERATION.md)를 따른다.

아래 내용은 이전 구현 단계의 기록이다. 당시의 ‘다음 작업’ 및 검사 수는 그 단계 기준이며 위 최신 안내가 우선한다.

2026-09-09. 실제 장비 설정이나 모델 가중치를 변경하지 않은 소프트웨어 구현이다.

## 지금 화면에서 가능한 일

`장비 · 보정 → 로봇 촬영 설정`에서 촬영 설정 팝업을 연다. 모델을 해제하고 로봇 연결을 해제한 상태에서 변경한다. 한국어·영어·중국어·태국어를 재시작 없이 적용한다.

- 이동 후 안정 시간, 단계 제한 시간, 검증 기록을 등록한다. 설치 전에는 미등록으로 저장할 수 있다.
- 프레임 시점 검증 탭에서 선택한 촬영 조건의 최대 영상 지연과 검증 기록을 등록한다. 검증되지 않은 시간을 기본값으로 채우지 않는다.
- 검증된 촬영·집기 보정 파일을 선택하거나 `촬영·집기 보정 만들기`에서 측정 자료와 자세를 묶어 새 파일을 등록한다.
- 저장만으로 카메라나 로봇을 연결하거나 움직이지 않는다. 취소는 설정을 바꾸지 않는다. 새 보정 파일을 만든 후 부모 설정창을 취소하면 파일은 남지만 활성 설정으로 등록되지 않는다.

## 좌표 변환 방식

전체사진의 동일한 기준점들에 대해 두 개의 측정된 평면 변환을 사용한다.

1. 해당 물체가 근접 영상 중심에 오도록 카메라를 맞췄을 때의 로봇 도구 XY.
2. 해당 물체의 집기점을 집게에 맞췄을 때의 로봇 도구 XY.

단순한 고정 XY 오프셋으로 카메라·집게 관계를 가정하지 않는다. 각 변환은 기존 보정 모듈의 6개 이상 계산점과 4개 이상 독립 검증점, 별도 측정 세션, 잔차 및 영역 검증을 통과하고 승인 기록이 있어야 한다. 동일한 원본 전체사진 좌표·촬영 조건·품목·검사면 높이·렌즈 조건의 두 자료를 묶는다. 영역 밖 좌표는 외삽하지 않는다.

전체 촬영 X/Y/Z/R, 근접 촬영 Z/R, 집기 Z/R, 이동 높이, 물체 내 집기 비율, 장착 부위와 경로 검증 기록을 묶는다. 전체사진의 물체 중심은 카메라 이동에, 등록된 물체 내 비율은 집기에 적용한다. 임의 회전 물체의 방향 추정이나 물체별 적응 집기점은 이번 방식에 포함되지 않는다. 그 경우 고정 집기 비율·R을 사용할 수 있는지 따로 검증하거나 모델을 확장해야 한다.

장착 링크의 운동이나 왜곡 때문에 두 평면 변환이 요구 오차를 만족하지 못하면 이 보정을 사용하지 않는다. 실제 로봇 운동학/카메라 외부 파라미터 모델로 확장해야 한다. 검증 기록이 충돌 회피를 계산해 주지는 않는다. 수직 상승 → 검증된 이동 높이에서 수평 이동/방향 변경 → 촬영 높이 하강의 전체 경로와 카메라/케이블/그리퍼 여유를 실물로 검증해야 한다.

## 프레임 시점

기존 D405 미리보기의 수신 시간을 곧바로 노출 시간으로 쓰지 않는다. `CaptureGate`는 요청 이전 수신 프레임을 버리고, 요청 이후 최초 프레임을 기준으로 장치 시각이 진행한 이후 프레임을 선택한다. 설치 시 측정한 **노출부터 호스트 수신까지의 최악 지연 상한**과 장치 시각 진행을 이용해 노출 시각의 보수적인 하한을 계산한다. 이 하한이 새 촬영 요청 시각 이후일 때만 저장한다. 장치 시각의 최대 1% 빠른 진행을 계산상 허용하며 이 가정과 지연 상한도 설치 조건에서 확인해야 한다.

`acquired_at`은 정밀한 노출 시각 측정값이 아닌 위 조건에 의한 하한이다. 촬영 응답에 기준 장치 시각·수신 시각·검증 기록·지연 상한을 남긴다. 시간값 누락/역행/비정상 점프, 세션·시리얼·영상 크기 변경, 오래된 프레임은 거부한다. 기한 안에 조건을 만족하지 못하면 회차는 실패해야 한다. 이 방식은 물리 지연 검증을 대체하지 않는다.

근거: [RealSense 프레임 메타데이터](https://github.com/realsenseai/librealsense/blob/master/doc/frame_metadata.md), [공식 프레임 API](https://github.com/realsenseai/librealsense/blob/master/include/librealsense2/hpp/rs_frame.hpp). 특정 D405 펌웨어/Windows 드라이버에서 노출 메타데이터가 제공된다고 가정하지 않았다.

원본 쓰기는 한 번에 하나만 수행한다. 중단 이후 쓰기 결과를 회차에 전달하지 않으며, 진행 중 쓰기를 취소할 수 없어도 추가 저장 작업을 계속 쌓지 않는다. 미리보기 연결은 유지한다. 파일 시스템 쓰기 자체가 멈춘 경우 강제 중단할 수 없는 스레드가 남을 수 있으므로, 새 운영 실행기에서는 저장 기한 실패·로봇 정지를 먼저 처리하고 종료 시 남은 쓰기의 완료 여부를 감시해야 한다.

## 장치 연결 계약

- `build_scan_profile`은 설치 설정 버전·보정 식별값·로봇 운전 파일 식별값·카메라 세션·준비 확인 후 로봇 연결 식별값을 회차에 고정한다.
- `StationRobotPort`는 기존 Magician 통신 어댑터를 별도 장치 스레드에서 사용한다. 연결만으로 준비 상태가 되지 않으며 명시적인 준비 확인이 필요하다. 모델 추론을 이 스레드에서 실행하지 않는다.
- 이동 요청은 `ScanJournal`에 저장된 현재 요청과 일치해야 한다. 근접 이동은 저장된 전체사진의 물체를 다시 보정해 목표 위치가 일치하는지 확인한다. 로봇 재연결/준비 상태 재확인으로 연결 식별값이 바뀌면 옛 회차를 거부한다.
- `CaptureMotion`은 이동 전 요청과 경로를 기록하고, 상승/수평 이동/하강을 하나씩 명령한다. 명령 완료 응답 뒤 실제 자세를 다시 읽어 검증한다. 응답 수신만으로 다음 촬영을 허용하지 않는다. 중단·기한 초과·기록 실패·위치 불일치 후 자동 재전송하지 않는다.
- 기존 로봇 작업자도 `OwnedAdapter`를 사용한다. 동일 로봇 제어 폴더의 소유권을 얻은 뒤 통신을 열고, 통신 종료까지 보유한다. 서로 다른 운영 폴더를 쓰는 다른 프로그램까지 제어하는 전역 장비 잠금은 아니다.
- `StationCameraPort`는 연결된 기존 `CameraProcess`를 사용하며, `tick()`으로 저장 완료 응답을 받아 `ScanSequence.complete()`에 전달한다. 정지 시 회차 취소와 별개로 즉시 로봇 작업자의 `stop_motion()`을 호출해야 한다. 저장 실패 때문에 정지 요청이 생략되어서는 안 된다.

## 남은 연결

현재 실행되는 기본 운영 화면은 이전 연속 검사 화면이다. 이번 새 촬영 모듈을 그 버튼에 임시로 연결하지 않았다. 다음 변경에서 회차 실행기를 중심으로 다음을 함께 연결한다.

1. 전체/상세 모델 준비와 촬영 요청·이동 요청의 실행 및 감시.
2. 왼쪽 저장 전체사진, 오른쪽 상세사진·기본 이유·VLM 설명, 회차 물체 선택.
3. 새 보정 묶음을 사용하는 로봇 운전 프로필 UI 및 두 보정의 측정 안내. 현재 보정 생성창은 **검증 완료된 두 측정 파일을 묶는 기능**이며 자동 측정 기능은 아니다.
4. 모든 상세 검사 뒤 OK/NG 분류, 보류 제외. 전체사진 좌표와 상세 판정 증거를 동시에 확인하는 새 분류 계획이 필요하며, 기존 고정 카메라 집기 계획을 그대로 재사용하지 않는다.
5. 새 회차 이력·보존·백업, 상세 결과의 기존 VLM 큐 연결. 모델 비교와 실제 정확도/처리 시간 평가는 실물 준비 후 수행한다.

설치 전 소프트웨어 검증은 `tests/test_station_devices.py`에 있다. 측정 값처럼 생긴 수치는 임시 테스트 파일에만 주입하며 실제 운전 설정에 저장하지 않는다.
