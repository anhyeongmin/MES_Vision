# 검사 이력 · 원본 보관 · 백업

14단계 구현. **4 검사 이력**에서 사용한다. 실제 제품 정확도·장비 동작·현장 처리량 검증은 포함하지 않는다.

## 검색과 검토

기간(PC 현지 시간, 시작 이상·끝 미만), 품목 이름/ID, 물체·검사·회차 ID, 판정, 불량 종류, 검토, VLM, 로봇, 보존 상태를 조합하고 `조회`를 누른다. 100건씩 보여주며 전체 조건의 검사 건수, 물체 ID 수, 재검사 건수, 정상/불량/보류 건수를 집계한다. 판정 건수에는 재검사가 포함된다. 물체 ID는 추적 회차 내 식별자이며 장면을 벗어났다가 돌아온 실물의 영구 식별자는 아니다.

첫 페이지는 새 검사를 반영하고 이후 페이지는 조회 시점의 상한을 유지한다. 검색은 별도 스레드에서 수행하며 이전 검색의 늦은 응답으로 새 조건을 덮어쓰지 않는다. `미검토 이상`은 미검토 불량·보류를 조회한다. 불량 종류의 `미등록 이상`은 NG_UNKNOWN이다.

이력 선택 시 저장 원본과 당시 판정 근거를 보여준다. `검토 기록`은 확인자와 내용을 남기며 이전 검토는 이벤트에 보존한다. 기본 판정은 바꾸지 않는다. `별도 보존`은 같은 원본 프레임의 모든 물체를 정리에서 보호한다. 사유를 비워 저장하면 해제한다. 기존 색인이 없으면 경고를 표시하며, `저장 · 백업 관리 → 이전 기록 색인 갱신`에서 원본 해시를 검증하고 색인을 채운다.

## 검색 전체 내보내기

현재 페이지에 한정하지 않고 적용된 검색 조건의 전체 기록을 새 폴더로 내보낸다. 기존 폴더를 덮어쓰지 않는다.

- `inspections.csv`: UTF-8 BOM, UTC ISO 시각, 품목/물체/검사 ID, 판정·불량 코드·검토·VLM·로봇·보존 상태. 수식으로 해석될 수 있는 문자열을 문자로 처리한다.
- `report.json`: 적용 검색 조건, 집계, 검사 결과·기준·설정, VLM 요청/결과, 검토·로봇 이벤트.
- `evidence/`: 원본 포함을 선택하면 프레임·물체 이미지·검사 JSON·스냅샷 명세를 프레임당 한 번 복사한다. 원본 제외 시에도 원본 무결성 검증과 근거 내보내기는 수행한다.
- `export-manifest.json`: 파일별 SHA-256과 크기. 파일 변경 확인용이며 전자서명은 아니다.

긴 파일 작업은 별도 스레드에서 수행한다. 작업 중에는 종료를 기다린다. 실패하면 최종 폴더 대신 `.partial-*` 중간 폴더가 남으며 사유 확인 후 사용자가 정리할 수 있다. 대량 내보내기는 범위와 원본 크기에 따라 시간·메모리가 필요하다. 장시간·대규모 성능 검증은 17단계에서 수행한다.

## 보존과 용량

모델을 해제하고 카메라·로봇 연결을 해제한 뒤 VLM OFF 상태에서 저장 관리를 연다. VLM 워커 종료를 기다리고 검사 회차·GPU·분석·로봇 작업 잠금을 확인한다.

초기 기준은 정상 30일, 불량 180일, 보류 365일, 미등록 저장물 7일이다. 원본 용량 알림은 100 GiB, 최소 디스크 여유는 5 GiB다. 프레임·물체 원본의 여유분까지 확보되지 않으면 새 결과 저장·공개를 중단한다. 원본 용량 알림은 저장 관리에서 용량 확인 시 표시하며 자동 삭제를 유발하지 않는다.

1. 운영 폴더 밖의 보관 위치를 지정하고 `보존 설정 저장`.
2. `정리 미리보기`에서 대상·보호 사유·확인 필요 오류 확인.
3. `검증 후 보관 이동`의 건수·용량·목적지를 확인하고 실행.

같은 프레임의 모든 기록이 보존 기간을 지나야 이동한다. 별도 보존, 미검토 보류/미등록 이상, 미색인 기록은 기본적으로 보호한다. 미검토 보호는 설정에서 해제할 수 있다. 미리보기는 15분간 유효하며 정책·파일·대상 변경 시 다시 확인한다.

전체 복사본과 스냅샷 해시를 검증한 뒤 이력/VLM 경로를 새 위치로 연결하고, 운영 `inspections` 아래의 확인된 중복 원본만 제거한다. 심볼릭 링크·Windows 접합점 경로를 거부한다. DB 이력과 보관 원본을 유지하여 이후 조회·내보내기가 가능하다. 같은 드라이브로 옮기면 디스크의 남은 공간은 증가하지 않는다.

미등록 저장물은 저장 후 공개가 취소됐거나 중단되어 이력에 연결되지 않은 폴더다. 보존 기간이 지난 폴더만 별도 보관하며 정상 검사 이력이나 로봇 대상으로 등록하지 않는다. 이동 도중 중단되면 DB 작업 기록을 남긴다. `중단된 보관 작업 복구`가 양쪽 파일을 대조하여 이어가며, 손상·예상 외 파일은 삭제하지 않고 확인 필요로 남긴다. 미완료 이동을 해결하기 전 새 이동·백업은 차단한다.

## 백업과 복원

`백업 만들기`는 운영 DB·검사 원본·VLM/로봇 이력, 등록된 모든 품목/장비 버전의 모델·기준·참조 파일, 외부 보관 원본과 미등록 보관물을 새 폴더에 복사한다. SQLite 백업 API로 WAL의 커밋도 포함한다. 과거 버전의 등록 자산이 없으면 완전한 백업으로 표시하지 않는다.

`backup.json`에 상대 파일·해시·경로 대응을 기록한다. `백업 검증`은 누락/변경, 경로 이탈, 매핑, DB 무결성을 검사하며 백업을 변경하지 않는다. 프로그램 설치본·Python 환경·공통 DINOv2/VLM 기본 모델·운영 폴더 밖의 미등록 원시 학습 데이터는 별도 확보한다. 완전한 PC 이미지 백업은 아니다.

`새 폴더에 복원`은 기존 운영·백업 위치 밖의 존재하지 않는 폴더만 허용한다. `runtime`에는 운영 자료, `assets`에는 외부 등록 자산을 두고 카탈로그 경로를 연결한다. 검사 당시 JSON·이미지의 내용과 해시는 바꾸지 않으며 그 안의 과거 경로 문자열은 당시 메타데이터로 보존한다.

복원 시 VLM OFF, 미완료 분석 취소, 로봇 RECOVERY, 기존 명령 계획은 과거 기록으로 전환한다. 보관 설정을 초기화하므로 새 장치에서 다시 지정한다. `복원본 실행`을 직접 누르면 별도 창을 연다. 기존 운영 데이터는 덮어쓰지 않는다. 복원본에 장비를 연결하기 전 기존 창의 장치를 해제하고 설치·보정 기준을 확인한다.

```powershell
.\.venv\Scripts\python.exe scripts\verify_storage.py
```
