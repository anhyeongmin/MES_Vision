# VLM 재로딩 대기 개선 · 2번

2026-09-07. 실제 소스에 기본 30초의 유휴 모델 유지 정책을 적용했다. 1번 화면 갱신 개선은 그대로 유지한다.

## 동작

- 마지막 분석이 완료된 뒤 대기열이 비어도 모델을 최대 30초 유지한다. 이 기간에 다음 요청이 들어오면 같은 모델 프로세스를 재사용한다. 실제 요청이 없으면 ON만으로 미리 모델을 적재하지 않는다.
- 유휴 기간 첫 확인에서 사용하지 않는 생성 캐시를 정리하고, 모델을 소유한 자식 프로세스에서 CUDA 여유 메모리를 읽는다. 이후 유휴 중 1초마다 확인하며 2,048MiB 미만이면 모델을 해제한다. 확인 실패/2초 응답 제한 초과도 해제로 처리한다.
- OFF, 작업자 종료, 검사 우선 요청, VLM 병행을 허용하지 않는 검사 모델의 사용권, 유지 시간 만료, 모델 프로세스 비정상 종료 시 해제한다. 모델 종료 확인 후에 GPU 잠금을 풀며, 모델을 유지하는 동안 잠금을 먼저 풀지 않는다.
- 검사 모델의 기존 병행 허용 기준(모델 적재 후 여유 12GiB 이상, 전체 20GiB 이상)은 변경하지 않았다. 유휴 메모리 확인은 실시간 메모리 예약을 보장하지 않는다.
- 작업자 인자 `keep_alive_seconds`는 기본 30, 범위 0~300초이며 0은 대기열이 비면 즉시 해제한다. `min_free_mib`는 기본 2048이다. `idle_seconds`는 기존 검사 종료 후 대기 간격이므로 서로 다른 설정이다. 이번 단계에서 새 설정 UI는 추가하지 않았다.
- runtime에 `WARM_IDLE`, 만료 예정 시각, 여유 메모리, 적재 횟수, 마지막 해제 사유를 기록한다. 결과 metrics에 모델 재사용 여부, 해당 요청의 모델 준비 시간, 작업자가 요청을 가져온 뒤 결과를 받은 시점까지의 처리 시간을 추가했다. 3번의 진행 상태 UI는 별도 작업이다.

## 검증

전체 **432개 시험 통과(71.536초)**. 새 유지 정책 회귀 시험 12개는 같은 프로세스 재사용, 시간 만료 후 재적재, 유지 비활성, OFF 및 무요청 ON, 검사 우선권, 비병행 모델 사용권, 메모리 부족/감소/확인 실패, 자식 프로세스 장애, 종료 및 잘못된 설정을 검증한다. 기존 VLM 취소·시간 제한·기본 판정 보존 및 저장 관리 시험도 통과했다.

PySide6 버튼 이벤트 검증 **13개 통과**. 유지 중 OFF 해제, 분석 중 OFF 취소, 완료 이력과 기본 검사 근거 유지, 종료를 확인했다.

RTX3090에서 실제 로컬 Qwen 모델과 합성 자료로 요청 2건을 실행했다. 첫 완료 뒤 대기열을 1.5초 비워 둔 다음 두 번째 요청을 추가했다. 같은 PID를 유지했고 총 적재 횟수는 1회였다.

| 측정 | 첫 요청 | 유지 중 다음 요청 |
|---|---:|---:|
| 모델 준비(자식 생성·로딩·무결성 확인) | 18.12초 | 0초 |
| 작업자 처리 시간(준비 포함) | 22.28초 | 3.39초 |

두 번째 요청의 등록 시작부터 완료와 유휴 유지 확인까지 관찰 시간은 3.66초였다. 유휴 유지 중 검사 우선 요청의 GPU 잠금 확보 대기는 307.7ms였으며 자식 PID가 제거된 것을 확인했다. 원래 검사 JSON 해시는 변하지 않았다.

이 수치는 **합성 자료 1쌍의 동작 검증**이며 반복 벤치마크, 지연 상한, 제품 불량 정확도, 카메라·로봇 운전 검증이 아니다. 모델 순수 추론 속도를 바꾼 작업이 아니며 첫 요청이나 유지 시간 만료/우선권 반환 후 요청에는 모델 준비 시간이 다시 필요하다. 노트북에서 실제 비전/VLM 병행 부하와 메모리 여유를 측정한 후 유지 시간을 확정해야 한다.
