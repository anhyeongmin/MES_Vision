# 12 · 카메라 픽셀 → 로봇 XY 보정

다중 대응점으로 평면 원근 변환을 계산하고, 독립 확인점으로 오차를 검사하며, 검증 기록을 연결한 보정만 좌표 변환에 사용하는 프로그램을 구현했다. PySide6 대응점 편집·영역 표시·오차·XY 확인창을 포함한다. 실제 D405·Dobot 측정값이나 운전용 보정을 등록하지 않았다.

## 적용 조건

현재 방식은 **높이가 정해진 평면의 2D 위치**를 변환한다. 원본 영상 픽셀에서 렌즈 왜곡을 보정한 뒤 호모그래피로 로봇 기준 좌표계의 X/Y(mm)를 계산한다. 평면 물체와 원근 변환의 관계는 [OpenCV 공식 설명](https://docs.opencv.org/5.0/tutorials/features/homography/homography.html)을 기준으로 했다.

작업대 크기만 입력해 픽셀을 mm로 환산하지 않는다. 카메라 원점과 로봇 원점, 회전 방향, 원근 효과를 대응점으로 연결해야 한다. 검사면의 높이는 알려져 있어야 하며 허용 높이 차이를 벗어나거나 높이가 미상인 경우 변환을 차단한다. 높이 허용값은 XY 오차를 자동 보증하지 않으므로 현장에서 그 높이 변동까지 시험해야 한다.

표면의 보정 높이와 로봇 TCP의 집기 Z는 별도 값이다. 그리퍼·흡착컵 오프셋과 집기 방법은 별도 검증한다. 회전 R도 이미지에서 자동 추정하지 않으며 품목별 집기 정책에서 명시적으로 전달한다. 물체 중심을 안전한 집기점으로 단정하지 않는다.

## 계산·검증 규칙

| 항목 | 구현 |
|---|---|
| 계산점 | 최소 6개 fit 대응점. 수치 정규화 후 SVD로 호모그래피를 계산 |
| 독립 확인점 | 최소 4개 check 대응점. 계산과 다른 측정 회차이며 좌표를 중복 재사용할 수 없음 |
| 이상 대응점 | 자동으로 숨기거나 제거하지 않고 모든 점의 오차를 보고 |
| 오차 기준 | 계산점 최대 오차, 확인점 최대 오차와 RMS를 명시적 mm 기준으로 검사 |
| 영역 기준 | 적용 다각형은 측정점이 둘러싼 범위 안에 있어야 함. 확인점도 적용 영역에 분포해야 하며 면적 비율을 검사 |
| 불안정 계산 | 일직선 배치·특이 변환·수치적으로 불안정한 대응·변환 분모가 영역 안에서 0이 되는 경우 거부 |
| 변환 범위 | 원본 영상의 승인된 적용 영역 밖이나 왜곡 보정 후 측정 범위 밖이면 거부. 외삽하지 않음 |
| 사용 승인 | 수치 검사를 통과해도 AWAITING_ACCEPTANCE. 검토한 검증 기록을 명시적으로 연결해야 ACCEPTED |

허용 오차와 확인점 범위 비율은 현장 기준으로 입력한다. 합성 예제의 숫자는 실물 기본값이 아니다. 최소 점 수와 면적 비율만 충족했다고 전체 작업 영역의 정확도가 입증되는 것은 아니다. 모서리·중앙·실제 집기 위치에 확인점을 충분히 배치하고 최종 작업 조건에서 측정해야 한다.

렌즈 처리는 두 가지를 지원한다.

- `none_verified`: 영상이 이미 보정됐거나 잔여 왜곡이 허용되는 조건을 측정·검증한 경우. 근거 이름이 필수다.
- `opencv_brown5`: OpenCV 정의의 카메라 행렬과 k1/k2/p1/p2/k3 계수. 반복 역변환 후 다시 투영해 수렴을 확인한다.

알 수 없는 왜곡 모델은 거부한다. D405 SDK에서 얻은 계수를 이름 확인 없이 OpenCV 계수로 복사하면 안 된다. SDK의 좌표·왜곡 정의와 현재 RGB 영상의 보정 여부를 장비 연결 때 확인해야 한다. 이미 보정된 영상에 중복 보정을 적용하지 않는다. 현재 설치 환경 OpenCV 5.0.0의 `undistortPoints(..., P=..., criteria=...)`를 사용한다.

## 설정 변경과 무효화

보정에는 품목, 카메라 ID, 마운트 변경 버전, 촬영 설정 버전, 로봇 기준 좌표계, 툴 좌표계, 영상 해상도·전처리 목록, 검사면 Z·허용 차이, 렌즈 모델, 측정점, 적용 영역, 오차 기준이 함께 저장된다.

실행 시 조건이 다르면 변환하지 않는다. 대응점을 수정하면 화면의 기존 계산·승인·변환 결과가 즉시 무효화된다. 다시 계산하고 검증 기록을 연결해야 한다.

보정 식별자는 이름과 전체 내용 해시를 결합한다. 같은 이름을 쓰더라도 점·기준·검증 기록이 바뀌면 다른 보정으로 취급한다. 저장 파일은 덮어쓰지 않으며 읽을 때 파일 해시와 측정점 재계산 결과를 대조한다. 행렬만 수정하고 해시를 다시 만든 경우도 측정점 재계산과 다르면 거부한다. 계산 라이브러리 버전도 저장하고 다른 버전에서는 재검증을 요구한다.

설정 ID 일치는 물리 카메라가 실제로 움직이지 않았음을 감지하는 기능이 아니다. 카메라·툴·로봇 기준을 바꿨을 때 현장 프로그램과 운영자가 변경 버전을 갱신해야 한다. 자동 기준점 점검·실제 카메라 연결은 현장 통합 범위다.

## 지금 실행하기

프로젝트 폴더의 PowerShell에서 새 출력 경로를 지정한다.

```powershell
# 합성 측정점, 계산 초안, 합성 검증 기록을 연결한 파일 생성
.\.venv\Scripts\python.exe scripts\calibration.py demo --output runtime\calibration-demo

# 대응점 편집·계산·오차·영역·XY 확인창
.\.venv\Scripts\python.exe scripts\calibration.py ui --input runtime\calibration-demo\points.json
```

창에서 `보정 계산 · 오차 확인`을 누른다. 통과하면 `검증 기록 연결`에 검토 기록의 이름/경로를 입력한다. 그 후 원본 픽셀 X/Y를 입력하면 로봇 XY(mm)가 표시된다. 실물 자료 없이 이름만 입력하는 것은 현장 검증이 아니다. 현재 예제는 화면에 합성 시험 자료로 표시된다.

대응점 파일은 계산·독립 확인 역할, 측정 회차, 원본 픽셀 XY, 로봇 XY를 포함한다. 현재 확인창은 유효한 형식의 측정점 파일을 불러와 편집한다. 카메라 영상 클릭·로봇 위치 자동 읽기와 전체 설정 입력 화면은 후속 제품 UI/장비 통합 단계에서 연결한다.

명령 방식으로 실행할 수도 있다.

```powershell
.\.venv\Scripts\python.exe scripts\calibration.py fit --input runtime\calibration-demo\points.json --output runtime\calibration-demo\new-draft.json
.\.venv\Scripts\python.exe scripts\calibration.py accept --input runtime\calibration-demo\new-draft.json --reference SYNTHETIC-REVIEW-ONLY --output runtime\calibration-demo\new-accepted.json
.\.venv\Scripts\python.exe scripts\calibration.py map --input runtime\calibration-demo\new-accepted.json --context runtime\calibration-demo\context.json --pixel 75 90 --plane-z-mm 20 --kind synthetic
```

map에는 현재 촬영·로봇 좌표계 조건과 높이·자료 종류를 명시해야 한다. 초안·실패한 보정·조건 불일치로는 변환할 수 없다. fit 명령은 수치 검사 실패도 검토 가능한 보고서로 저장한다. 종료 코드 0이 사용 승인이라는 뜻은 아니며 status/failures를 읽어야 한다. 실패한 결과의 accept는 거부한다.

## 로봇 엔진 연결

`map_target(calibration, inspection, object_id, pixel, context, plane_z_mm=..., r_deg=..., grasp_policy_version=...)`는 현재 품목·물체·영상 해상도·전처리를 확인하고 11 단계 MappedTarget을 반환한다. 선택 픽셀이 해당 물체 내부인지도 확인한다.

로봇 프로필과 SceneStamp의 calibration_version에 동일한 보정 identity를 연결해야 계획을 만들 수 있다. 보정이 바뀌면 장면 식별도 갱신하여 기존 계획을 무효화한다. 계산된 XY는 집기 성공·도달 가능·충돌 회피를 의미하지 않으며 11의 작업 범위·운전 준비 검사와 실물 검증이 추가로 필요하다.

기본 설정 `configs/calibration/unconfigured.json`은 active_calibration=null이다. 실제 보정을 자동 활성화하지 않았다. 실제 Dobot 어댑터도 계속 차단되어 있으며 이 프로그램은 카메라나 로봇 명령을 보내지 않는다.

## 장비 준비 후 측정 순서

1. 카메라·조명·작업대·로봇 기준·툴을 고정하고 RGB 해상도와 전처리를 확정한다.
2. 실제로 검사할 표면 높이의 평면에 기준점을 배치한다. 원본 영상 픽셀과 동일 기준의 로봇 XY를 정확하게 대응시킨다.
3. 작업 영역의 가장자리와 내부에 계산점을 확보하고, 별도 측정 회차의 확인점을 충분히 확보한다.
4. 품목의 요구 집기 오차에 맞춰 허용 오차와 영역 기준을 입력한다. 입력 오차나 잘못된 대응을 수정할 때 확인점을 계산점으로 편입해 성능을 좋게 보이게 하지 않는다.
5. 수치 결과와 실제 독립 위치 오차·높이 변화 영향을 검증한 뒤 기록을 연결한다. 이후 그리퍼 오프셋·접근 경로·로봇 동작까지 별도로 확인한다.

## 검증

```powershell
.\.venv\Scripts\python.exe scripts\verify_calibration.py
```

전체 기능·회귀 시험 209개(신규 좌표 보정 22개), PySide6 offscreen 조작 10개, 저장 재불러오기·CLI 변환 일치, 보정으로 생성한 MappedTarget의 모의 집기·분류까지 통과했다. 결과는 `artifacts/calibration-check/report.json`, 화면은 해당 실행 폴더의 `calibration-viewer.png`에 있다.

합성 데이터는 알고 있는 원근 변환으로 생성했다. 오차가 거의 0인 것은 수치 계산의 재현 결과이며 실제 D405·Dobot 정밀도 수치가 아니다. 실제 측정·노트북·장비 운전은 시험하지 않았다. 다음은 13 단계 PySide6 제품 UI 통합이다.
