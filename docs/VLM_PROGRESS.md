# VLM 진행 상태 표시 · 3번

2026-09-07. VLM 추가 분석 화면에 전체 작업 상태와 선택 요청의 진행 상태를 추가했다.

- 전체 상태: 모델 준비 중, 검사 우선으로 대기, GPU 사용 순서 대기, 추가 분석 중, 모델 유지 중, 새 요청 대기, OFF, 작업자 중단/상태 확인 필요를 구분한다. 상단의 처리 중 건수는 모델 준비와 분석을 모두 포함한다.
- 전체 단계 경과 시간과 모델 유지 종료까지의 시간을 표시한다. 선택 요청은 요청 이후 경과 시간을 표시하고 완료/실패/취소 등 종료 상태에서는 시간을 고정한다. 재요청한 경우 최초 등록 이후의 전체 경과 시간이며 순수 모델 추론 시간이 아니다.
- 완료 결과에 모델 재사용 기록이 있으면 재로딩 생략을 표시한다. 대기열 가득 참은 자동 처리 대기처럼 표시하지 않고 다시 요청해야 함을 안내한다.
- RUNNING 행의 작업 ID와 실행 시도 토큰이 runtime과 일치할 때만 모델 준비/분석 단계를 표시한다. 다른 요청이나 이전 시도의 상태를 붙이지 않는다.
- 작업자는 같은 단계에서도 약 1초 간격으로 상태를 기록한다. 단계 시작 시각은 같은 단계의 상태 갱신으로 초기화하지 않는다. 상태가 6초 넘게 갱신되지 않으면 계속 분석 중이라고 표시하지 않고 확인 필요로 안내한다. 이것은 상태 표시이며 검사/로봇 제어에 새 명령을 보내지 않는다.
- OFF/취소 요청은 이전 분석 상태보다 우선한다. DB 조회 실패 시 마지막 조회 결과임을 표시하고, 정상 조회가 돌아오면 새 상태를 표시한다.
- 단계/경과 시간은 기존 0.5초 주기의 백그라운드 조회 결과로 갱신한다. 숨긴 페이지의 자동 조회 생략, 표의 변경분 갱신, 동일 근거 이미지 캐시, 기본 판정/VLM 의견 분리를 유지한다.
- 한국어·영어·중국어·태국어를 지원한다. 완료 예상 시간이나 임의 진행률은 표시하지 않는다. 모델 유지 카운트다운은 유휴 해제 정책의 시간으로, 분석 완료 예측이 아니다.

## 검증

전체 444개 시험 통과(81.348초). 이후 상단 요약의 ‘분석 중’을 ‘처리 중’으로 다듬고 번역을 갱신한 최종 소스에서 관련 49개 시험을 추가 확인했다(6.073초). PySide6 실제 버튼 이벤트 검증 13개도 통과했다.

새 시험 12개는 현재 단계와 실행 토큰 연결, 오래된 상태/취소 우선 처리, 완료 시간 고정, 보류된 요청 안내, 네 언어 문구와 서식, 이미지 재읽기 없이 단계 갱신, 조회 실패 복구, 상태 기록 간격, 실제 모의 모델 자식 프로세스의 장시간 분석 중 상태 갱신 및 검사 우선 대기 전환을 확인한다.

4개 언어 × 5개 상태(준비/검사 우선 대기/분석/모델 유지/응답 갱신 중단)의 화면 20장을 생성하고 새 상태 레이블의 높이가 내용에 맞는지 검증했다. 한국어와 태국어 화면을 시각 확인했다. 긴 표 셀은 줄임 표시와 툴팁을 사용하고, 선택한 요청의 전체 상태는 상세 영역에서 줄바꿈해 표시한다.

검증 자료는 `artifacts/vlm-progress-step3`에 보관한다. 화면 자료는 별도의 합성 시험 대기열에서 만들었으며 운영 이력에 등록하지 않았다. 실제 장비 연결 및 노트북 실운전 검증은 아직 수행하지 않았다.
