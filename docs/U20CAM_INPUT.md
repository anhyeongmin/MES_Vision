# U20CAM 카메라 입력 전환

U20CAM-720P용 USB 카메라 입력을 추가하고, 장치 선택·미리보기·전체/상세 촬영·원본 저장·검사 연결을 변경했다. 실제 카메라와 로봇은 이번 작업에서 연결하거나 구동하지 않았다. 연결 수신, 노출, 촬영 지연과 렌즈 보정은 장비 준비 후 확인해야 한다.

## 프로그램에서 사용하는 순서

1. **장비 설정 → 카메라 종류 → U20CAM / USB 카메라**를 선택한다.
2. **장치 다시 검색**을 누르고 실제 연결한 카메라를 고른다. 검색만으로 영상 촬영이나 로봇 이동을 시작하지 않는다.
3. 기본값은 **MJPEG / 1280×720 / 30 fps**다. 해상도와 프레임 속도는 목록에서 선택한다.
4. 설정을 저장한 다음 **카메라 연결**을 누른다. 연결만으로 검사를 시작하지 않는다.
5. 검사 중단은 미리보기를 유지한다. 카메라 연결이 끊어지거나 영상이 멈추면 기존 오류 처리로 검사를 중단하고 재연결을 요구한다.

처음 만든 장비 설정은 USB 카메라가 기본이다. 기존 D405 기록은 자동으로 USB 장치로 해석하지 않는다. 해당 기록에서는 종류를 바꾸고 장치를 다시 선택해야 한다. 장치, 해상도, 전송 형식, 속도, 노출 설정 변경은 촬영 조건 버전을 갱신하므로 이전 보정을 그대로 사용할 수 없다.

## 촬영 후보와 실제 연결 확인

| 해상도 | MJPEG | YUY2 |
|---|---:|---:|
| 1280×720 | 30 fps | 10 fps |
| 800×600 | 30 fps | 20 fps |
| 640×480 | 30 fps | 30 fps |
| 320×240 | 30 fps | 30 fps |

후보는 [제조사 U20CAM-720P 사양](https://www.inno-maker.com/product/u20cam-720p/)에 따른다. 장치 검색만으로 이 모드들이 현재 USB 연결에서 지원된다고 표시하지 않는다. 연결 시 드라이버가 보고한 해상도·속도·전송 형식을 대조하고, 실제 프레임 크기와 색상 구조도 확인한다. 이 확인은 드라이버의 협상 결과 확인이며 실제 처리량·화질 측정을 대신하지 않는다.

자동/수동 노출을 설정할 수 있다. 수동 노출값은 운영체제·드라이버 단위이므로 기존 D405 수치를 복사하면 안 된다. Windows DirectShow에서는 자동 노출 설정 요청의 성공을 확인하지만 해당 속성의 읽기 기능은 제공되지 않아 실제 자동 노출 동작은 실물로 확인해야 한다. 수동값은 가능한 드라이버 읽기값과 대조한다.

## 장치 식별과 영상 저장

- Windows는 DirectShow, Linux는 V4L2 경로를 사용한다. 현재 개발 PC의 Windows 소프트웨어 경로를 시험했으며 Linux 실장비 시험은 하지 않았다.
- 검색된 장치 경로에 대응하는 식별자를 저장한다. 연결할 때마다 다시 검색해 현재 인덱스를 찾고, 연결 중 장치 목록 변경도 확인한다. 카메라를 찾지 못했을 때 다른 카메라나 기본 웹캠으로 대체하지 않는다.
- Linux에서는 `/dev/videoN` 번호 대신 `/dev/v4l/by-id` 또는 `/dev/v4l/by-path` 식별 경로가 있어야 목록에 표시한다. USB 포트나 장치 경로가 바뀌면 다시 선택하고 보정 조건을 확인해야 한다.
- 매 연결에 새 세션 ID를 부여한다. 원본 RGB, 세션·장치·프레임 순서·PC 수신 시각 정보를 저장하고, 상세 결과와 전체 사진의 연결을 유지한다.
- 수신과 원본 저장·모델 처리는 기존 별도 프로세스 경로를 사용한다. USB 드라이버 호출이 멈춰도 UI 종료가 무기한 기다리지 않도록 제한 시간을 유지한다.

## 로봇 이동 후 새 사진을 선택하는 조건

이 UVC 경로는 센서의 노출 시각을 받지 않는다. PC에서 읽기가 끝난 시각을 센서 시각으로 기록하지 않는다.

장비 설치 후 **로봇 촬영 설정 → 프레임 시점 검증**에서 해당 촬영 조건의 노출부터 PC 수신까지 전체 지연 상한과 측정 기록을 등록해야 한다. 미리보기는 이 등록 전에도 가능하지만 검사 회차는 등록이 필요하다.

UVC 검사 사진은 `PC 읽기 완료 시각 − 검증된 지연 상한`이 촬영 요청 이후인 경우에만 채택한다. 요청 전에 받은 영상, 오래된 영상, 역행한 순서·수신 시각, 다른 장치·세션, 변경된 해상도와 변환된 영상은 사용하지 않는다. 이 방식은 등록한 지연 상한이 실제 카메라·노출·드라이버·부하 조건을 포함한다는 전제가 필요하다. 지연 측정과 오래된 영상 방지의 실물 검증은 남아 있다.

UVC 카메라의 렌즈 왜곡이나 내부 파라미터는 추정값으로 채우지 않는다. 실측 렌즈/좌표 보정 자료를 준비해야 한다. 합성 학습의 가상 카메라 높이를 로봇 설정에 넣지 않는다.

## 검증 기록과 라이선스

**관련 소프트웨어 회귀 시험 279개가 통과했다.** `artifacts/uvc-transition/`에 변경 전 소스, 최종 `tests-verified.log`, 설정 화면과 의존성 출처를 보관했다. 시험에는 카메라 대신 주입한 프레임·드라이버를 사용했으며 실제 촬영 성능 승인이 아니다. 학습 모델의 운영 등록과 실제 이미지 보완 학습은 별도 단계다.

장치 검색 의존성은 [cv2-enumerate-cameras 1.3.3](https://pypi.org/project/cv2-enumerate-cameras/1.3.3/)으로 고정했다. 받은 Windows wheel의 해시를 PyPI 배포 정보와 대조했고, 해당 배포물의 MIT 저작권·허가문을 `licenses/cv2-enumerate-cameras-1.3.3-MIT.txt`에 보관했다. 기존 OpenCV와 모델·UI 의존성은 교체하지 않았다. DirectShow 속성 처리는 [OpenCV 공식 구현](https://github.com/opencv/opencv/blob/4.x/modules/videoio/src/cap_dshow.cpp)을 확인했다.
