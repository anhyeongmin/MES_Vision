# 11 · Dobot 제어 구조와 모의 동작

**2026-09-06 변경:** 실제 Magician 시리얼 어댑터와 운영 UI 연결을 추가했다. 아래는 11단계 당시의 기록이며 현재 연결·설정·미검증 항목은 [운영 수정 문서](OPERATOR_REVISION.md)를 따른다. 실제 장비가 없는 상태에서 물리 동작 성공을 주장하지 않는다.

검사 결과를 받아 물체 하나의 집기·분류 계획을 만들고, 명령 접수·동작 완료·집기/놓기 확인을 구분하는 제어 엔진을 구현했다. 현재 실행 가능한 어댑터는 명시적인 가상 로봇뿐이다. 실제 Dobot Magician SDK·시리얼 연결과 물리 운전은 구현·검증하지 않았다.

## 동작 범위

검사→판정은 기존 04~10 모듈의 책임이다. 11 모듈은 판정된 검사, 물체 ID, 좌표 변환 결과, 운전 설정, 현재 장면 식별을 받는다. 보정 계산 자체는 12 단계이며, 여기서는 보정 버전과 유효성을 대조한다.

한 물체의 순서는 다음과 같다.

| 상태 | 작업과 완료 조건 |
|---|---|
| PREPARE_PICK | 품목·판정 근거·현재 장면·보정·집기 정책·로봇 상태 확인, 계획과 사용 프레임 예약 |
| APPROACH_PICK | 집기점 위 이동 높이로 접근, 명령 완료와 목표 위치 확인 |
| DESCEND_PICK | 설정된 집기 높이로 내려감 |
| PICK | 흡착 또는 그리퍼 작동 명령; 접수만으로 성공 처리하지 않음 |
| VERIFY_PICK | 별도 집기 확인 결과가 true여야 진행 |
| LIFT_PICK | 이동 높이까지 상승 |
| MOVE_PLACE | 해당 물체의 OK/NG/REVIEW 목적지 위로 이동 |
| DESCEND_PLACE | 설정된 놓기 높이로 내려감 |
| PLACE | 물체 놓기 명령 |
| VERIFY_PLACE | 별도 놓기 확인 결과가 true여야 진행 |
| RETRACT | 이동 높이로 후퇴 |
| RECAPTURE | 현재 동작 종료. 다음 집기는 새 프레임과 새 계획이 있어야 가능 |

화면 전체의 종합 NG가 아닌 **선택한 물체의 판정**으로 목적지를 정한다. 동일 프레임의 다른 물체를 연속으로 집는 계획은 실행하지 않는다. 계획이 예약된 프레임은 중단·실패·재시작 후에도 소비된 상태로 남는다. 다음 동작에는 새 촬영 결과가 필요하다.

## 시작 전 차단 조건

- 실제 실행 요청, 실제 어댑터: 항상 차단. SDK/포트 자동 검색이나 장비 명령 코드는 없다.
- 미검증 운전 설정, 미설정 좌표·집기 정책·목적지·확인 방법: 차단.
- 현재 검사·물체·품목·프레임과 좌표 변환 결과가 다름: 차단.
- 보정 버전·집기 정책 버전·장면 버전·연결 회차가 다름: 차단.
- 촬영 시간이 오래되거나 미래로 표시됨: 차단. 최초 명령 전에도 다시 확인한다.
- 저장 판정이 실제 검사 근거로 재평가한 판정과 다름: 차단.
- 촬영/작업 영역/수량의 미확인 사유, 물체 가장자리·겹침·추출 문제: 차단.
- 좌표가 설정한 작업 범위를 벗어나거나 집기 원본 픽셀이 대상 밖에 있음: 차단.
- 로봇 연결·현재 위치·빈 그리퍼 상태가 미확인되거나 이동 높이에서 준비되지 않음: 차단.
- REVIEW 물체는 기본 차단. 해당 품목에 검증된 보류 이동 허용·목적지·집기 계획이 별도로 있어야 격리할 수 있다.

작업대 가로·세로 숫자만으로 픽셀을 로봇 mm로 바꾸지 않는다. Pose는 `robot_base_mm_deg`, 원본 집기점은 별도 픽셀 좌표다. 영상의 상자 중심을 실물 집기점으로 자동 채택하지 않는다. 합성 예제만 가상의 중앙 집기점을 명시적으로 제공한다.

현재 작업 범위 검사는 설정한 직육면체와 회전 범위의 수치 확인이다. **Dobot의 실제 도달 영역·충돌·케이블·그리퍼 간섭을 판정하는 경로 계획기가 아니다.** 실제 관절 이동 경로·높이·장애물 회피·정지 동작은 설치 후 검증해야 한다. 예제 숫자는 Dobot 사양이나 권장 운전값이 아니다.

## 실패·정지·복구

명령 ID별 INTENT를 저장한 뒤 전송하고, ACCEPTED와 COMPLETED를 별도 기록한다. 접수 응답으로 다음 동작을 시작하지 않는다. 동시에 진행 중인 명령은 하나이고, 자동 재전송·자동 재시도는 없다.

시간 초과, 거절, 실패, 결과 미확인, 다른 명령 ID의 응답, 목표 위치 불일치, 집기/놓기 확인 실패, 연결 변경, 장면·보정 변경이 발생하면 정지를 요청하고 FAULT에 남긴다. 정지는 물체를 자동으로 놓는 명령을 보내지 않는다. 잡고 있거나 잡았는지 불명확한 물체는 그 상태를 유지한 채 확인을 요구한다.

일반 정지 요청은 확인 응답이 있으면 STOPPED, 없으면 FAULT다. 정지 접수나 프로그램 상태 표시가 물리 안전을 증명하지는 않는다. 소프트웨어 정지는 물리 비상정지를 대체하지 않는다.

로봇 기록은 SQLite에 저장하며 같은 저장소에는 제어기 하나만 실행할 수 있다. 진행 중 프로세스가 죽으면 재시작 시 RECOVERY로 진입한다. 과거 명령을 자동 전송하지 않는다. 복구에는 정지 상태·연결·물체를 잡고 있지 않다는 별도 확인과 확인 기록이 필요하며, 복구 후에도 새 촬영을 요구한다.

`SimulatedMagician.reconcile_empty()`는 사람/센서의 실제 상태 확인을 대신하는 **시험 전용 조작**이다. 실제 로봇 복구 구현으로 사용할 수 없다. 프로그램 강제 종료 시 실제 로봇이 어떻게 정지하는지, 장비 자체 감시·정지 방식은 장비 연결 단계에서 별도로 검증해야 한다.

저장 실패 시 새 이동을 보내지 않고 가능한 정지를 요청한다. 파일 오류가 계속되면 기록 성공을 가장하지 않고 예외를 반환한다. 전체 디스크 보존 정책·운영 오류 화면·알림은 14/15 단계에서 통합한다.

## 실행

프로젝트 폴더의 PowerShell에서 실행한다. 결과 경로는 새 폴더여야 한다.

```powershell
# 기본 설정 확인: 실제 운전 false, 좌표·높이·목적지는 null
.\.venv\Scripts\python.exe scripts\robot.py configuration

# 계획만 저장하며 모의 명령도 실행하지 않음
.\.venv\Scripts\python.exe scripts\robot.py preview --output runtime\robot-preview

# 정상 물체 집기·분류 모의 실행
.\.venv\Scripts\python.exe scripts\robot.py simulate --output runtime\robot-ok

# 불량 물체 모의 분류
.\.venv\Scripts\python.exe scripts\robot.py simulate --decision NG --output runtime\robot-ng

# 집기 확인 실패: VERIFY_PICK에서 FAULT
.\.venv\Scripts\python.exe scripts\robot.py simulate --fault-stage VERIFY_PICK --fault unverified --output runtime\robot-pick-failed

# 물체를 든 뒤 정지: 자동 놓기 없이 STOPPED
.\.venv\Scripts\python.exe scripts\robot.py simulate --stop-stage LIFT_PICK --output runtime\robot-stopped
```

보류 격리 예제는 `--decision REVIEW --allow-review`를 명시한다. `--allow-review` 없이 REVIEW 계획은 생성 단계에서 차단한다. 지정할 수 있는 오류는 reject / timeout / disconnect / failure / unknown / unverified / wrong_id / wrong_pose다. unverified는 확인 단계, wrong_pose는 이동 단계에 지정해야 의미가 있다.

simulate는 가상 시계를 사용해 실제 대기 없이 진행한다. 예제 시간이 실제 Dobot의 이동/응답 시간이라는 뜻은 아니다. 의도한 오류 시나리오가 실행된 경우도 명령 종료 코드는 0이며, 운전 결과는 `report.json`의 state와 cycle_verified를 읽어야 한다. 설정이나 계획 생성 실패는 종료 코드 1이다.

출력에는 검사 결과, 계획 전체·해시, 명령 ID·목표 위치, 상태 전환·오류·정지 이력, 사용 프레임과 판정/보정/집기 정책 출처가 남는다. `real_commands_sent=0`, `hardware_tested=false`, `synthetic=true`를 명시한다.

## 통합 인터페이스

- `build_plan(...)`: 원본 판정과 설정을 변경하지 않고 검토 가능한 PickPlan을 반환한다.
- `RobotController.start(plan, scene, now=...)`: 동일 장면·최신 계획·준비 상태와 프레임 중복을 확인한다.
- `tick(scene, now=...)`: 한 번에 명령 하나를 접수하거나 상태를 확인한다. 장면 변경은 새 SceneStamp로 전달해 진행 계획을 무효화한다.
- `stop()`: 진행 중단을 요청한다. 자동 놓기나 자동 재개를 하지 않는다.
- `recover(confirmation_reference=...)`: 명시적인 모의 상태 확인 후 기존 계획을 버리고 재촬영 상태로 돌아간다.

now와 observed_monotonic은 같은 프로세스의 단조 시계를 사용한다. 이전 프로세스의 시각·계획을 재시작 후 재활용하지 않는다. 장면 식별은 새 촬영·외부 물체 이동·보정/설정 변경 시 갱신해야 한다. 실제 제품에서는 UI 작업부가 주기적으로 tick을 호출하고 설정 변경을 전달하도록 13/15 단계에서 통합한다. 어댑터의 통신은 제한 시간 안에 반환하는 방식으로 구현해야 하며 UI 스레드에서 장시간 대기하면 안 된다.
