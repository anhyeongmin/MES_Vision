# MES Vision 개발 진행표

갱신일: 2026-09-06

현재 운영 UI와 실제 장치 연결의 기준은 [14단계 전 운영 수정](OPERATOR_REVISION.md)이다. 아래 선행 단계의 당시 시험 결과는 이력으로 유지한다. 8가지 선행 수정으로 상시 모델 적재, 실시간 추적, 최소 저장 연결과 실제 D405/Magician 연결 코드를 앞당겨 반영했다. 물리 장비 시험·실물 정확도·노트북 성능 검증은 아직 하지 않았다.

사용자 요청: 실제 물체·환경 없이 가능한 작업부터 순서대로 하나씩 처리한다. 장비 준비 여부는 사용자가 나중에 알린다.

## 현재 단계

- 완료: 01 시스템 구조 확정. 기준 문서: [SYSTEM_ARCHITECTURE.md](SYSTEM_ARCHITECTURE.md).
- 완료: 02 모델·라이선스 선정, 공식 파일 확보 및 무결성 확인. [선정 결과](MODEL_AND_LICENSE_REVIEW.md).
- 완료: 03 개발 환경 구축. GPU 추론·합성 데이터 학습·Windows UI 확인, 패키지 버전·고지 갱신. [환경 결과](DEVELOPMENT_ENVIRONMENT.md).
- 완료: 04 이미지 입력 기능. 사진·폴더·영상 공통 RGB 입력, 상태·오류·메타데이터, D405 미설정 경계. [사용법](IMAGE_INPUT.md).
- 완료: 05 검출·검사 연결 코드. 다중 물체 원본 추출·복수 결함·검사 어댑터·모의 결과, 실제 RF-DETR GPU 연결. [사용법](INSPECTION_PIPELINE.md).
- 완료: 06 학습 프로그램. 데이터 검사, 물체/불량 별도 학습, 정지·상태 복원, 평가·가중치 재사용 검증. [사용법](TRAINING.md).
- 완료: 07 데이터 관리·라벨링 준비. 로컬 라벨링 도구·수집/검토 이력·실물/회차 분리·네 종류 내보내기. [사용법](DATA_MANAGEMENT.md).
- 완료: 08 이상 탐지 프로그램. 검토한 정상 특징 저장·재불러오기·점수·영역·미설정 기준 보류. [사용법](ANOMALY.md).
- 완료: 09 VLM 연결. 저장 자료 후속 분석, PySide6 확인창 ON/OFF, 기본 근거와 설명 분리, 중단·복구·응답 검증·시간 제한·GPU 우선순위. [사용법과 한계](VLM.md).
- 완료: 10 판정 로직. 필수 검사·검증된 모델/기준 연결, 후보·이상 점수 경계, 복수 불량·오류 보존, 저장 재평가·화면 표시. [사용법과 검증 범위](DECISION.md).
- 완료: 11 로봇 제어 구조·모의 동작. 단일 물체 집기·분류 계획, 확인·시간 제한·정지·재시작 복구·동일 프레임 재사용 차단. [사용법과 한계](ROBOT.md).
- 완료: 12 좌표 보정 프로그램. 평면 원근 변환·독립 오차/영역 검사·렌즈 처리·저장 재계산 대조·PySide6 편집/XY 확인·모의 로봇 연결. [사용법과 적용 조건](CALIBRATION.md).
- 완료: 13 PySide6 통합 UI 및 운영 수정 8가지. 실제 입력·연속 추적/검사·품목 버전·장비 설정·검사 원본/동작 연결·선택형 VLM. [현재 실행 안내](OPERATOR_REVISION.md).
- 완료: 14 저장·조회 확장. 조건 검색·전체 보고서/원본 내보내기, 보존/용량 기준, 검증된 보관 이동과 복구, 미등록 저장물 보호, 등록 자산 포함 백업·새 폴더 복원. [사용법](STORAGE.md).
- 완료: 15 오류 처리. 카메라 프로세스 격리·시간 제한, 검사 진행 감시·메모리 오류, 저장 실패·오류 기록 복구, 로봇 대기 명령 폐기, VLM 오류 격리, 조치 확인·진단 내보내기. [사용법과 검증 범위](RECOVERY.md).
- 완료: 17 시험 도구·검증 계획. 전체 장면 재생 평가, 누락/오판/보류/오류 집계, 연속 운영 계약 시험, 실제 3090 GPU 및 VLM 경합 측정, 현장 시험표. [사용법](VALIDATION.md) · [측정 결과](VALIDATION_RESULTS.md).
- 다음: 장비 준비 통보 후 실물 학습·카메라/로봇·노트북·현장 연속 시험. 사용자 결정에 따라 16 설치 배포는 이 검증 후 진행한다.
- 기존 자산: RF-DETR Small 공식 가중치, RTX 3090 추론 확인, 설치 스크립트, 의존성 고정 목록.
- 주의: 기존 환경 준비가 모든 검사 모델의 실행·학습·배포 준비 완료를 뜻하지 않는다.
- 현장 의존 작업: 사용자 장비 준비 통보 전까지 대기. 가상 데이터 결과를 현장 검증으로 기록하지 않는다.

## UI 개발 순서 — 사용자 확정

- 먼저 PySide6 제품을 완성한다. 현재 01~17 단계와 장비 준비 후 현장 검증을 우선한다.
- PySide6 버전 완성 후 C# WinForms 버전을 추가한다. 현재 병행 구현하지 않는다.
- Python 검사·판정·저장·VLM 엔진을 공통으로 재사용하고, 화면은 명령과 결과를 주고받는 역할로 분리한다.
- 후속 WinForms 단계에서 프로세스 간 통신, 시작·종료·오류 복구, 두 UI의 동일 입력/결과와 배포 구성을 검증한다. 통신 방식과 .NET 버전은 그 단계에서 확정한다.

선행 단계에서 필요한 공통 인터페이스와 최소 오류 처리는 그 단계에서 작성한다. 이후 해당 단계에서 기능을 완성한다. 예를 들어 06 학습 코드를 위해 데이터 형식 초안을 먼저 정하고, 07에서 라벨링 운영 도구와 지침까지 완성한다.

실물 모델 학습을 완료했다는 주장은 실제 데이터가 있는 경우에만 한다. 시험 데이터로 학습 루프가 실행되는 것은 코드 검증이다. D405 연결, 실제 로봇 명령, 노트북 실행은 해당 장비를 실제로 사용했을 때만 확인 완료로 표시한다.

## 변경 기록

- 2026-09-05: 기존 모델 준비 상태를 확인하고 01 설계 문서와 전체 진행표를 작성했다. 추가 모델 설치·학습·UI 구현·실물 동작은 수행하지 않았다.

- 2026-09-05: 사용자 동의에 따라 Windows 설치형 프로그램 + Python 검사 엔진 + PySide6 화면으로 설계 방향을 확정했다. UI 도구의 배포 조건 검토는 02에 포함하며, UI 구현 자체는 아직 진행하지 않았다.
