# 성능 개선 4 — VLM 이미지 입력 연산 개선

2026-09-06. 기본 Qwen3.5-4B의 영상 패치 투영을 같은 Conv3d 가중치의 선형 연산으로 실행한다. 모델 교체·양자화·입력 축소·출력 길이 단축은 적용하지 않았다. 기존 BF16, SDPA, thinking OFF, 프롬프트와 생성 한도를 유지한다.

## 적용 원리와 범위

이 모델의 영상 입력은 이미 패치 단위로 펼쳐져 있다. 각 패치 크기가 Conv3d 커널/stride와 같고 padding=0, dilation=1, groups=1이므로 패치마다 출력 위치가 하나다. 같은 가중치를 펼쳐 `linear`로 곱할 수 있다. [Conv3d 정의](https://docs.pytorch.org/docs/2.9/generated/torch.nn.Conv3d.html)와 [linear 정의](https://docs.pytorch.org/docs/2.9/generated/torch.nn.functional.linear.html)를 확인했다.

3090/Windows의 원래 BF16 Conv3d 경로가 영상 입력의 병목이었다. 연산별 탐색에서 vision 호출 8.80초, 첫 토큰 9.68초였고, 별도의 동일 크기 무작위 입력 Conv3d만 약 6.87~7.50초가 걸렸다. 원인 확인용 동기화 계측이며 최종 성능 수치와 구분한다. CUDA Graph도 작은 연산에서 탐색했으나 최종 구현은 패치 투영 변경만 포함한다.

- 실행 프로필 `linear_patch_v1`을 기본 사용하고 `standard`는 비교용으로 남긴다. 설치된 transformers 5.16.1, torch 2.9.1+cu128, Qwen 구현 파일 SHA256 및 실제 투영 구조가 검증값과 일치해야 한다. 불일치하면 명시적으로 실패하며 다른 구조에 자동 적용하지 않는다.
- 특정 모델 인스턴스의 패치 호출만 바꾼다. 전역 함수·설치 라이브러리·원본 가중치 파일을 수정하지 않는다. 가중치와 bias Parameter, state_dict 키를 유지하고 프로필 복원/종료 시 원래 호출을 복원한다.
- **수학적으로 같은 투영이지만 부동소수점 결과와 생성 문장이 완전히 같지는 않다.** 다른 실행 커널의 반올림 차이로 단어/공백/관찰 범위가 달라질 수 있다. 결과 provenance에 실행 프로필과 구현 해시, 비트 단위 동일성 보장 없음이 기록된다. 프롬프트 버전과 기본 검사 판정은 유지한다.
- 추가 관찰은 계속 별도 VLM 결과이며 기본 OK/NG·로봇 명령을 바꾸지 않는다. 기존 VLM OFF·취소·타임아웃·기본 검사 우선권을 유지한다. 같은 프로세스에서 임의의 동시 프로필 전환을 지원하는 운영 UI는 추가하지 않았다.

## 3090 비교

합성 저장 이미지의 4조건(이상 표시+참조, 정상+참조, 영어 이상 관찰+참조, 참조 없는 이상 관찰)을 각 방식 2회씩 실행했다. 원래/개선 순서를 교차하고 첫 워밍업 요청은 따로 기록했다. 총 16회, 방식별 8표본이다. 모델은 한 번 적재해 같은 가중치와 입력으로 비교했다.

| 측정 중앙값 | 기존 | 개선 |
|---|---:|---:|
| 응답 완료(호출 전체) | 11.58초 | 3.84초 |
| 생성 시작 후 첫 토큰 | 8.31초 | 0.47초 |

응답 완료 시간은 약 67% 감소했다. 모델 적재·큐 대기·촬영·로봇·검사 병행 시간은 포함하지 않는다. 출력 길이는 모델이 생성한 길이 그대로이며 같은 고정 토큰 수의 벤치마크는 아니다. 정상 케이스는 JSON 공백만 달라져 토큰 수가 다르기도 했다. 추가 실행 가중치를 보유하지 않으며 비교의 최대 PyTorch 할당은 양쪽 약 8,873MiB였다. 이는 전체 GPU 메모리 사용량이 아니다.

모든 응답이 기존 JSON 검증과 토큰/시간 제한을 통과했다. 8쌍의 needs_review는 모두 같았다. 원시 응답은 2쌍이 같고, 관찰 문장은 4쌍이 같았다. 영어 케이스는 shows/displays 등 표현이 바뀌었고, 참조 없는 경우에는 개선 방식이 검은 선에 더해 흰색 사각형도 언급했다. 해당 저장 crop을 직접 확인했으며 두 도형 모두 보인다. 기존 검사 파일의 모든 해시는 유지됐다. 이 소수 합성 케이스는 실물 불량 정확도나 일반적인 응답 동등성을 검증하지 않는다.

재현 도구 `scripts/benchmark_vlm_projection.py`, 근거 `artifacts/inference-optimization/step4/comparison/report.json`에 각 원문·프롬프트·시간·입력 정보가 있다. 실행 프로필 차이가 있으므로 과거 VLM 문장과 반드시 같은 결과를 기대하지 않는다. 노트북·실물·장시간·GPU 병행 성능은 현장 검증 대상이다.

## 실제 소스 최종 확인

- 전체 **409개 시험 통과(78.510초)**. 기본 판정 보존, VLM ON/OFF·취소·타임아웃, 기존 추적·저장·UI 회귀 시험을 포함한다.
- 실제 백그라운드 Qwen 작업자에서 추가 관찰 2건이 완료됐고 원래 검사 JSON 해시가 유지됐다. 실행 provenance는 `linear_patch_v1`이다.
- 추가 작업 중 RF-DETR 검사 요청을 넣어 VLM 프로세스 종료·작업 PENDING 복귀·검사 재개를 확인했다. 해당 1회 양보 대기 309.04ms는 지연 상한을 보장하는 수치가 아니다. VLM 중단 후 모델 PID가 남지 않았다.
- 실제 작업자 근거는 `worker/gpu.json`, 전체 시험은 `all-tests.log`, 요약은 `summary.json`이다. 작업자 검증과 CPU 회귀 시험은 함께 실행했으므로 작업자 시간은 위 단독 비교의 성능값으로 합산하지 않는다.

모델 적재/가중치 무결성 검사는 별도 준비 시간이다. 기존 작업자는 대기 작업이 없어지면 모델을 해제하므로 새 묶음의 첫 요청에는 재적재 시간이 추가될 수 있다. 위 3.84초는 적재된 모델의 처리 시간이며 화면에서 요청한 순간부터의 전체 대기 시간을 의미하지 않는다. GPU 우선권·유휴 해제 정책은 변경하지 않았다.
