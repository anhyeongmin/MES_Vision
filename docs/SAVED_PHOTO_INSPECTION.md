# 저장사진 검사와 ASH 학습 모델 연결

2026-09-11. 새 불량 모델을 저장사진 검사에 연결하고, 실제 검사 화면의 상세사진에도 불량 후보 표시선을 추가했다. 카메라·로봇 연결 없이 사진과 실제 학습 가중치로 확인할 수 있다.

## 화면에서 확인하기

1. 프로젝트의 `MES Vision.cmd`로 프로그램을 실행한다.
2. **2 품목 설정 → 저장사진 검사**를 누른다. 운영 모델이 준비돼 있다면 먼저 **모델 해제**를 누른다.
3. **학습 자료 불러오기 → 사진 검사 시작**을 누르면 등록된 합성 검토 사진 12장을 처리한다. 정상/NG01~NG06, 빈 전체사진, 여러 물체 전체사진, 기존 오검출 사례를 포함한다. 학습 분할이 아닌 기존 시험 분할의 사진이다.
4. 사진 목록에서 한 장을 선택한다. 원본의 물체를 클릭하거나 물체 목록을 선택하면 오른쪽에 해당 영역과 불량 후보 이름·점수가 표시된다.
5. **저장 결과 열기**로 이전 `results.json`을 열면 재추론 없이 확인할 수 있다.

직접 사진을 넣으려면 **상세사진 · 불량 검사** 또는 **전체사진 · 위치 검출**을 선택한 뒤 **사진 선택**을 누른다. 촬영 사진과 합성 사진의 출처도 구분한다. 한 번에 1~200장을 처리한다. 파일 선택 후 실제 처리 역할은 사진 목록에 표시된다.

전체사진은 물체 위치만 검출하며 불량 모델을 실행하지 않는다. 상세사진은 중앙의 물체 하나가 식별될 때 물체 영역을 잘라 새 불량 모델에 전달한다. 여러 물체가 잡히거나 대상이 불확실하면 불량 검사를 생략하고 이유를 표시한다.

이 창의 **선택 물체 확대**는 저장 원본을 잘라 확대한 것이다. 별도로 촬영한 근접사진으로 표시하거나, 서로 다른 전체·상세 합성사진을 같은 실제 물체로 자동 연결하지 않는다. 기존 검사 운영 화면의 **전체 촬영 → 개별 근접 촬영 → 상세 결과 선택** 흐름은 유지된다.

## 연결한 모델

| 역할 | 가중치 | 후보 수집 기준 |
|---|---|---|
| 전체 위치 | `artifacts/training/ash-synthetic-v2-first/overview-objects/inference.pth` | 0.05 |
| 상세 물체 | `artifacts/training/ash-synthetic-v2-first/detail-objects/inference.pth` | 0.20 |
| 상세 불량 | `artifacts/training/ash-reinforced-v3/detail-defects/inference.pth` | 0.10 |

설정은 `configs/inspection/ash-trained-v3.json`이다. 기존 검증 분할에서 선택한 후보 기준을 그대로 사용하며, 시험 결과를 보고 다시 조정하지 않았다. 세 역할 모두 RF-DETR Small 1.9.4, 기존 평가와 동일한 `standard`, batch 1 설정이다. 가중치 SHA256과 클래스 순서·NG01~NG06 대응을 확인하고 로드한다. 추가 모델 다운로드나 새 의존성 설치는 없다.

표시 점수는 모델 점수이며 실제 불량 확률로 해석하지 않는다. 주황색 불량 영역은 후보이고 정답 주석이 아니다. 최종 판정과 후보는 별도 정보다.

## 판정과 장비 연결

현재 합성 모델만으로 실물 OK/NG를 승인하지 않는다. 정상 참조·미지 불량 검사와 실물 판정/화질 기준이 아직 없으므로 저장사진의 최종 품질 판정은 보류다. **알려진 불량 후보 없음**도 정상 확정을 뜻하지 않는다.

저장사진 경로는 `model_file` 입력을 유지하며 카메라 프레임이나 실제 로봇 회차로 바꾸지 않는다. 운영 품목·판정 규칙·카메라 보정·운전 설정은 이번 연결로 자동 등록되지 않는다. VLM을 실행하거나 분석 요청을 자동 등록하지 않으며, 기본 후보와 이유를 보는 데 VLM은 필요하지 않다. 기존 운영 VLM ON/OFF와 비동기 설명은 유지된다.

추론은 별도 프로세스에서 실행한다. 중단·창 닫기는 프로세스 종료를 요청하고 종료된 뒤 창을 닫는다. 진행이 180초간 갱신되지 않으면 중단한다. 운영 모델이 GPU를 점유하면 별도 저장사진 모델을 동시에 적재하지 않는다.

## 저장과 재현

실행마다 `artifacts/operation/photo-inspections/<실행 ID>/`에 원본 복사본, 물체별 잘라낸 이미지, 검사 결과, 모델 정보, 출처와 해시를 저장한다. `results.json`에서 결과를 다시 열 수 있다. 운영 검사 이력의 자동 분류 기록으로 등록하지 않는다. 실패·중단 작업은 완성 결과로 공개하지 않으며 로그와 남은 중간 자료를 자동 삭제하지 않는다.

이번 144장 확인 결과는 `artifacts/model-ui-integration/inference/results.json`이다. 등록 사진 12장의 실제 UI 작업자 실행 결과 경로는 `artifacts/model-ui-integration/ui-worker-verification.json`에 있다.

## 확인 결과

- 실제 가중치로 전체사진 18장과 상세사진 126장을 처리했다. 검사 오류는 없고, 불량 후보 110개의 잘라내기 좌표를 원본 좌표로 되돌린 결과를 검사했다.
- 상세사진의 기존 정답과 비교하면 TP 108, 추가 FP 2, FN 0이다. 기존 평가와 같은 합성 사진이며 새로운 독립 평가나 실물 성능 수치가 아니다. 정상 18장 중 1장의 NG04 오검출이 그대로 남아 있다.
- 기존 정상 사진 오검출과 NG03 사진의 추가 NG04 후보를 검토 목록에 포함했다. 누락 검출 성공 사례만 선별하지 않았다.
- 실제 창의 시작 → 별도 프로세스의 12장 추론 → 결과 저장·조회까지 확인했다. 한국어·영어·중국어·태국어와 두 창 크기에서 32장을 렌더링하고 실제 마우스 클릭으로 선택 연결을 확인했다. 한국어/태국어 화면을 직접 점검했다.
- 관련 자동 회귀 **274개가 통과**했다(72.992초). 결과 파일의 입력 모드·판정 검사를 마지막으로 강화한 뒤 관련 9개도 재확인했다. `artifacts/model-ui-integration/regression-final.log`, `reader-final.log`, 모델·좌표 확인 `verification.json`, UI 작업자 확인 `ui-worker-verification.json`을 참고한다.

다음은 U20CAM과 실물 준비 후 실제 사진 수집, 정상 참조와 판정 기준 구성, 보완 학습·독립 검증이다. 실제 촬영 지연·렌즈/좌표 보정·로봇 동작·노트북 성능은 별도 확인해야 한다.
