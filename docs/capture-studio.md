# 촬영 설정과 학습 영상 수집

환경설정 → 카메라 · 데이터 수집 → 실시간 촬영 조건 조절 / 학습데이터 수집.
검사 운영 화면에도 학습데이터 수집 버튼이 있습니다. 검사 모델을 해제한 상태에서 사용합니다.
기존 미리보기 카메라는 수집 창이 잠시 넘겨받고, 창을 닫으면 저장된 설정으로 다시 연결합니다.

## 촬영 조건

카메라 입력은 MJPEG 30fps 후보 중 선택합니다. U20CAM-720P 실기 확인 모드는 1280×720입니다.
노출·게인 범위는 Windows DirectShow 장치에서 읽습니다. 확인되지 않은 제어는 비활성화합니다.
전체 촬영 / 상세 촬영을 선택하고, 값을 바꾼 후 ‘미리보기에 적용’을 누릅니다.
‘전체·상세 촬영 조건 저장’은 두 조건을 장비 설정에 함께 저장합니다.
각 프로필에서 적용한 값이 해당 프로필의 저장 후보가 됩니다. 적용하지 않은 편집값은 저장하지 않습니다.
촬영 모드를 변경하면 ‘선택 모드로 재연결’한 뒤 사용합니다.

검사 중 전체·상세 촬영 요청에 맞는 조건을 적용한 뒤, 기존 검증된 영상 지연 범위를 이용해
적용 이전 프레임을 제외합니다. 촬영 조건 변경은 acquisition revision을 갱신합니다.
기존 검사 설정과 타이밍 검증은 변경된 조건에 맞게 확인해야 합니다.

## 녹화

1. 촬영 설정에서 조건을 미리보기에 적용합니다.
2. 학습데이터 수집에서 품목, OK/NG 분류, 학습용/독립 평가용을 선택합니다.
3. 필요하면 같은 실물 번호와 촬영 메모를 입력합니다.
4. 녹화 시작 → 녹화 중단 · 저장을 누릅니다.

저장 위치: 프로젝트의 `collections/recordings/날짜_시간_분류_고유번호/`.

- `NG04.mp4` 등: 원본 카메라 영상에서 오버레이·왜곡 보정 없이 인코딩한 영상.
  카메라 전송은 MJPEG, 저장 컨테이너는 MP4이며 네이티브 MPEG-4 인코더를 사용합니다.
- `recording.json`: 품목, 클립 분류, 수집 목적, 실물 번호, 촬영 조건, 완료 여부.
- `frames.jsonl`: 프레임 ID와 수신 시점, 영상 시간축 연결 기록.

촬영 중에는 품목·분류·조건 변경을 잠급니다. 파일 이름은 자동 생성하며 기존 파일을 덮어쓰지 않습니다.
녹화는 검사 모델·로봇·VLM 없이 가능합니다. 저장 공간 부족이나 카메라 오류는 화면에 표시합니다.
강제 종료된 녹화는 완료 상태로 처리하지 않습니다.

클립 분류는 사용자가 선택한 물체 종류이며, 불량 영역 정답을 자동 생성한 것은 아닙니다.
프레임 추출과 영역 라벨 검토는 기존 데이터 준비 과정에서 수행합니다.
독립 평가용 표시는 수집 목적 기록이며, 학습에 사용하지 않은 회차·실물을 실제로 분리해야 합니다.

## 확인 결과 (2026-09-14)

- 실제 U20CAM-720P 범위: 노출 -13~-1, 게인 0~100, 각 1단위.
- DirectShow에서 FPS·해상도 설정 후 MJPEG를 마지막에 지정하도록 수정.
- 1280×720 / MJPEG 확인, 수동 노출 상태 수신 속도 약 30.21fps.
- 실제 카메라 작업 프로세스의 조건 적용 → 녹화 → 저장 → 재생 확인: 77프레임, 약 30.03fps.
- 테스트 후 자동 노출 및 게인 0 복원. 영구 운영 설정은 변경하지 않음.
- 범위 제한, 두 프로필 저장, 촬영 요청 ID 유지, MP4 재생, 종료 처리 및 기존 검사 UI 회귀 테스트 통과.
- 실물 영상 테스트는 `artifacts/capture-studio-check`에 진단용으로 격리되어 있으며 학습 자료에 포함하지 않음.

실기 점검: `scripts/check_capture_studio.py --hardware`,
녹화 점검: `scripts/check_capture_recording.py --hardware`.
두 점검은 카메라를 사용하는 다른 프로그램을 닫은 뒤 수행합니다.
