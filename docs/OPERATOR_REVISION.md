# 14단계 전 운영 수정 8가지

후속 14단계 저장·조회 확장은 [저장·백업 사용법](STORAGE.md)에 반영했다. 아래 내용은 선행 운영 수정의 검증 이력이다.

2026-09-06. 사용자가 승인한 8가지 수정의 소프트웨어 구현 범위다. 실제 물품·설치 환경·Dobot은 아직 준비되지 않았다. 검증 기록 입력은 사용자가 수행한 현장 검증을 등록하는 기능이며, 입력만으로 물리 성능이 증명되는 것은 아니다.

## 실행과 저장 위치

프로젝트 루트의 `MES Vision.cmd`를 실행한다. `scripts/desktop.py`가 `mes_vision.operation.window.DesktopWindow`를 연다. 기본 저장 위치는 `artifacts/operation`이다. 이전 `artifacts/desktop`의 개발 확인 자료를 자동으로 가져오지 않는다. 기존 개발용 CLI와 `mes_vision.desktop.window`는 회귀 검증용으로 남아 있으며 운영 진입점에서 사용하지 않는다.

장비 없이도 품목의 초안을 만들고, 파일 등록 화면·조건 입력·VLM 설정·학습 도구를 확인할 수 있다. 품목을 저장한 뒤 **선택 품목 적용**으로 활성 버전을 지정한다. 기본 실행에는 가짜 제품이나 합격 결과가 없다.

## 장비 준비 후 연결 순서

1. **장비·보정 → 장치 검색**에서 D405 시리얼과 Dobot 포트를 확인한다. 장비 설정에 D405 시리얼·촬영 모드·설치/촬영 버전을 입력하고 카메라를 연결한다. Depth 스트림은 켜지 않는다.
2. 실제 화면을 확인한 뒤 카메라 연결을 해제하고, 남아 있는 마지막 영상 위에서 검사 영역·제외 영역을 지정한다. 작업대 실제 가로/세로, 영역 검증 기록을 저장한 뒤 다시 연결한다. 촬영 크기·노출 변경에는 새 촬영 조건 버전이 필요하다.
3. 품목을 적용하고 **현재 영상 수집**으로 원본을 저장한다. **품목 설정 → 데이터·학습**에서 실물 수집 프로젝트를 만들고 사진을 가져와 라벨링·검토·실물/회차 분할·내보내기를 진행한다. 데이터의 품목 ID는 품목 설정 ID와 같아야 한다.
4. 물체/불량 모델은 따로 학습한다. 정상 특징은 검토한 정상 내보내기로 구축한다. 학습·정상 특징 구축·평가는 모델 해제 및 VLM OFF 상태에서 시작한다. 실행 중에는 창을 닫지 못하며 저장 후 중단과 강제 종료를 구분한다. 완료된 모델은 품목 설정에서 파일을 선택해 등록한다.
5. 분리된 실물 검증 데이터로 촬영·불량·이상·형상 기준을 확인한 뒤 버전과 검증 기록을 등록한다. 형상 검사는 등록한 상대 영역의 특징 면적과 외곽 조건을 사용하므로 기준을 검증한 방향·정렬 조건이 필요하다. 현재 집기 기준도 물체 내부의 고정 비율 및 고정 방향이다.
6. **좌표 보정**에서 계산점 6개 이상과 별도 회차의 독립 확인점 4개 이상을 입력한다. 영상에서 점을 클릭하고 측정한 로봇 XY를 입력한다. 사용 영역·오차·렌즈 모델·검사면 높이를 검증한 보정만 등록한다. 지원하지 않는 렌즈 모델은 임의 변환하지 않으며, 확인한 보정 파일을 장비 설정에서 선택해야 한다.
7. 품목 집기 기준, 로봇 작업 범위·이동 높이·분류 위치·도구·디지털 입력·속도/가속도와 검증 기록을 등록한다. Magician은 독립 집기 센서 없이 명령 접수만으로 집기 성공을 판정하지 않는다. 센서가 준비되지 않으면 로봇 운전 준비는 완료되지 않는다.
8. Dobot의 초기 위치를 등록한 이동 높이의 대기 위치로 맞춘다. 설치 시 수동 위치 조정과 실제 센서/영역 확인은 장비 또는 제조사 도구로 수행하고, 동일 포트를 사용하는 제조사 도구를 닫은 뒤 이 프로그램에 연결한다. **로봇 준비 확인**은 이전 명령을 재전송하지 않고 빈 도구·정지 상태를 대조한다.
9. **품목 설정 → 모델 준비** 후 **실시간 검사 → 검사 시작**을 누른다. 처음에는 자동 분류가 OFF다. 선택한 현재 OK/NG 물체를 분류하거나 자동 분류를 켠다. 보류는 이동하지 않는다. 한 번에 하나만 집고, 동작 완료 후 집기 위치가 새 영상 3회에서 비워졌는지 확인한 다음 재검사한다. 분류 영역은 검사 영역 밖에 두거나 제외 영역으로 지정한다.

검사 중단은 새 검사와 새 로봇 요청을 중단한다. 이미 시작한 로봇 사이클은 완료하며 **로봇 정지**는 별도 중단 요청이다. 소프트웨어 정지 응답은 물리 비상정지 회로의 대체가 아니다. 불명확한 통신 결과는 자동 재전송하지 않고 준비 확인 또는 재연결을 요구한다.

## 판정과 이력의 의미

확정된 같은 추적 버전은 한 번 검사하고, 새 검사나 재검사는 새 기록을 남긴다. 이동·외관 변화·가림·연결 간격 초과 시 이전 현재 판정을 해제한다. 동일하게 생긴 물체가 영상 사이에 바뀌는 모든 경우를 식별할 수 있는 것은 아니다. 물체 간격·설치 고정·관찰 간격은 현장에서 검증해야 한다.

영상 품질/영역이 부적합하면 ‘촬영 조건 확인’으로 대기하며 정상/불량을 만들지 않는다. 원본 저장이 완료되기 전에는 운전 가능한 새 결과를 공개하지 않는다. 저장 완료 시점에 추적이나 검사 실행 상태가 바뀌었으면 현재 결과와 이력 등록을 취소하고 원본 경로를 `UNPUBLISHED_SNAPSHOT` 이벤트에 남긴다. 이 원본과 비정상 종료 중간 파일의 보존/정리는 14단계 대상이다.

결과에서 모델 판정 기준에 따른 NG 이유를 즉시 볼 수 있다. VLM은 저장된 당시 이미지/검사 근거/정상 참조/설명을 읽는 추가 의견이다. 현재 물체 판정과 저장 이력은 구분된다. 과거 이력에서는 집기를 요청할 수 없다.

## VLM과 GPU

실시간 모델이 적재된 뒤 여유 VRAM 12 GiB 이상이고 총 VRAM 20 GiB 이상이면 VLM 동시 사용을 허용한다. 부족하면 VLM은 모델을 해제할 때까지 대기한다. 검사 중단은 추적을 유지하므로 모델 해제와 다르다. VLM OFF는 큐 요청을 취소하고 진행 중인 별도 모델 프로세스를 중단하지만 완료 기록은 지우지 않는다. 다른 프로그램의 GPU 사용량 변동이나 메모리 부족은 실패로 표시하며 기본 판정을 VLM으로 대체하지 않는다.

메모리 조건은 공존 가능성을 위한 조건이며 처리 속도 보장이 아니다. 실제 모델·물체 수·카메라 해상도·VLM 동시 사용에 따른 지연은 현장 및 노트북에서 따로 측정한다.

## 검증 결과와 남은 범위

- 신규 45개와 기존 217개, 총 262개 검사를 배포된 소스에서 통과했다. 최종 실행 기록: `artifacts/operator-check/all-tests.log`.
- 운영 5개 화면 및 장치 검색 확인: `artifacts/operator-check/report.json`, `page-1.png`~`page-5.png`. 이번 검색에서 D405와 직렬 장치가 발견되지 않았다.
- 3090에 두 RF-DETR 인스턴스와 DINOv2를 적재한 반복 추론: `artifacts/operator-check/gpu.json`. 워밍업 약 26.1초, 반복 추론 중앙값은 전체 영상 검출 약 32.0ms·물체 1개 불량 검출 약 27.3ms·정상 특징 추출 약 18.7ms였다. 일반 가중치와 확인용 영상으로 측정했으며 카메라/저장/VLM/정상 특징 거리 검색/제품 정확도는 포함하지 않는다. 반복 중 모델 인스턴스 재생성은 없었다.
- 장비 프로토콜 검사는 주입한 전송/응답으로 분할 패킷·체크섬·시간 초과·중복 전송 억제·명령 번호/실측 위치 대조·DI 집기/놓기 확인을 시험했다. 실제 Magician 동작 성공 기록이 아니다.
- 실물 정상/불량 모델 학습, 최소 결함 가시성, 미등록 이상 민감도, VLM 설명 품질, 카메라 연결·렌즈·좌표 정밀도, 실제 집기/놓기, 장시간 연속 운전, RTX 5070 노트북 검증은 장비 준비 후 수행한다.
- 14단계는 보존/용량/백업/내보내기/검색·보고서 확장, 15단계는 복합 장애와 복구, 16단계는 설치 패키지, 17단계는 운영 성능/평가·출고 기준 검증을 이어간다. 이번 수정이 전체 제품의 출고 완료를 뜻하지 않는다.

## 구현 및 의존성

운영 코드는 `src/mes_vision/operation`, 원본 Magician 전송 구현은 `src/mes_vision/robot/magician.py`에 있다. `pyrealsense2==2.58.4.10922`, `pyserial==3.5`를 추가하고 설치 환경 및 배포 고지를 갱신한다. 제조사 DLL이나 PDF를 제품에 복사하지 않는다.

RealSense 패키지의 동봉 고지는 `licenses/dependencies/pyrealsense2-2.58.4.10922/licenses/LICENSE`, pyserial 3.5의 공식 고지는 `licenses/operation/pyserial-3.5-LICENSE.txt`에 보관했다. 후자의 원문 출처는 [pyserial v3.5 LICENSE](https://raw.githubusercontent.com/pyserial/pyserial/v3.5/LICENSE.txt)이며 SHA-256은 `f91cb9813de6a5b142b8f7f2dede630b5134160aedaeaf55f4d6a7e2593ca3f3`이다.

참조한 공식 자료: [RealSense SDK](https://github.com/realsenseai/librealsense), [Magician 통신 규약 V1.1.5](https://download.dobot.cc/product-manual/dobot-magician/pdf/en/Dobot-Communication-Protocol-V1.1.5.pdf), [DobotLink Protocol2 구현](https://github.com/Dobot-Arm/DobotLink/tree/main/Plugins/MagicDevicePlugin/Protocol2).
