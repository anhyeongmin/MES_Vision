# 13단계: 통합 검사 프로그램

**2026-09-06 변경:** 실제 실행 화면은 [운영 수정 8가지 및 사용법](OPERATOR_REVISION.md)으로 교체했다. 아래 내용은 교체 전 13단계 개발 검증 기록이다. 합성 예제·사진 시험·모의 집기는 현재 운영 화면에 없다.

프로젝트의 `MES Vision.cmd`를 더블클릭한다. 현재는 프로젝트의 Python 환경으로 실행하며 설치 패키지는 16단계에서 만든다. 웹 서버나 브라우저를 사용하지 않는다.

## 바로 확인하기

1. **검사** 화면의 `합성 예제`를 유지하고 **검사 시작**을 누른다.
2. 세 물체의 OK / NG / 보류를 확인한다. 두 번째 물체를 선택하면 균열 NG03과 표면 결함 NG06, 이상 탐지 오류의 근거가 함께 보인다. 고정된 합성 시험 결과이며 AI의 실물 정확도를 보여주는 데모는 아니다.
3. **선택 물체 모의 집기**로 보정된 시험 XY → 집기 → 분류 → 재촬영 요구를 확인한다. 보류 물체는 이동하지 않는다. 시험 장면의 유효 시간은 60초이며 시간이 지나면 새 검사부터 해야 한다.
4. VLM은 기본 OFF다. ON 후 새 검사를 실행하면 저장된 물체를 Qwen3.5-4B가 뒤에서 분석한다. **선택 물체 VLM 분석 열기**는 해당 검사·물체의 요청을 선택한다. 기존 OFF 요청은 자동 재개하지 않는다. 필요하면 VLM 화면에서 명시적으로 다시 요청한다.
5. **검사 이력**에서 저장 검사를 다시 열 수 있다. 이력 조회는 로봇 실행 권한을 만들지 않는다.

VLM을 끄면 대기/진행 요청은 취소하고 기본 판정 근거와 완료된 설명은 보존한다. VLM의 설명은 기본 판정이나 로봇 계획을 수정하지 않는다. 정상 참조·검사 기준 설명이 없는 분석은 그 제한을 표시한다.

## 각 화면

| 화면 | 연결된 기능 |
|---|---|
| 검사 | 합성 검사, 사진 RF-DETR 실제 추론, 여러 물체·불량 영역, OK/NG/보류, 즉시 기본 근거, 중단, 선택 물체의 VLM·모의 집기 |
| 품목 설정 | 품목 ID, 작업 공간 크기, 예상 수량, 일반 모델 후보 임계값, 학습 모델/정상 메모리/판정 정책 설정 가져오기, 저장 |
| 장비·보정 | D405/Dobot 준비 상태, 합성 또는 실측 보정점 편집 창, 데이터 라벨링 창, 모의 로봇 복구 |
| 검사 이력 | 최근 500건, 품목/검사 ID 검색, 무결성 확인 후 재열기, 저장 폴더 열기 |
| VLM 분석 | 전역 ON/OFF와 같은 큐, 대기·완료·실패·취소 상태, 기본 근거와 추가 의견, 선택 요청 재분석·취소 |

작업 공간의 가로·세로 입력은 픽셀→로봇 보정을 대신하지 않는다. 합성 예제는 항상 fixture-part와 합성 보정만 사용한다. 실물 모델 설정을 합성 예제에 적용하지 않는다. D405 연결·실제 Dobot 운전·실물 활성 보정은 여전히 미구현/미등록 상태다.

## 실제 사진과 학습 모델 설정

**사진 모델 시험**에서 사진 선택 후 검사한다. 제품 모델 미등록 시 로컬의 공식 COCO RF-DETR Small만 사용한다. 이를 제품 불량 검사로 간주하지 않으며 필요한 품목·촬영 기준이 없으면 보류한다. 사진을 읽지 못하거나 추론이 실패해도 합성 검사로 대체하지 않는다.

학습 가중치가 준비되면 JSON 모델 설정을 가져오고 **품목 설정 저장**을 누른다. 경로는 설정 파일 기준 상대 경로나 절대 경로로 작성한다. 물체 검출은 필수이며 나머지는 미등록할 수 있다. 미등록 검사는 그대로 판정에 반영된다.

```json
{
  "schema_version": 1,
  "product_id": "part-a",
  "objects": {
    "weights": "objects.pth",
    "sha256": "실제 파일 SHA256 64자리",
    "class_names": ["part-a"],
    "threshold": 0.4
  },
  "defects": null,
  "anomaly": null,
  "policy": null
}
```

불량 모델은 `defects`에 `weights`, `sha256`, 순서가 고정된 `class_names`, `threshold`, `class_codes`를 설정한다. `class_codes` 예시는 `{"0":"NG03","1":"NG06"}`다. 이상 탐지는 `anomaly: {"bank":"정상 메모리 폴더", "criteria":"기준 JSON 또는 null"}`로 등록한다. `policy`에는 10단계 실물 품목 판정 규칙 JSON 경로를 지정한다. 가져오기는 구조·경로·클래스를 확인하며, 실제 로딩에서 해시/체크포인트 클래스/정상 메모리·품목 연결을 다시 검증한다. 설정 파일은 코드나 셸 명령을 실행하지 않는다.

촬영 품질·작업 영역의 실물 검증 근거를 UI에서 임의 승인하는 기능은 없다. 실물 기준 및 정상 참조 등록 절차는 실물 준비 후 연결·검증한다.

## 실행·저장 구조

- 기본 저장 위치: `artifacts/desktop`. 설정/이력 SQLite, `inspections` 원본·물체 PNG·검사 JSON, `requests` 작업 요청/진단 기록, `vlm` 후속 분석 큐, `robot` 모의 동작 기록.
- 기본 검사 완료 시 무결성이 확인된 스냅샷을 이력에 등록한 후 VLM에 요청한다. VLM 등록 실패는 이미 저장한 기본 판정을 지우지 않는다.
- 검사 처리와 모델 로딩은 별도 프로세스에서 수행한다. 중단/종료 시 자식 프로세스를 종료하고 늦게 도착한 결과를 화면/이력/VLM에 게시하지 않는다. 부모 종료 감시와 180초 단건 제한이 있다.
- 취소 직전 완성된 미등록 스냅샷이나 작성 중 임시 폴더는 남을 수 있다. 자동 수거·교차 저장 복구·용량/보존/내보내기 정책은 14/15단계 범위다.
- 같은 저장 폴더에 대한 앱 중복 실행을 막는다. 다른 저장 폴더로 분리해 실행하는 것은 개발 시험용이다. 다중 앱 전체의 GPU 사용 조율은 아직 지원하지 않는다.
- 학습/보정/라벨링 엔진은 기존 모듈을 재사용한다. 학습 작업의 전체 운영 화면과 폴더·영상 연속 재생은 후속 연속 운전 시험 범위이며 현재 통합 검사는 사진 단건이다.

## 성능과 검증 범위

13단계 사진 시험은 **매 검사마다 모델을 불러오는 격리된 단건 실행**이다. RTX 3090 실제 UI 경로에서 합성 사진 파일로 RF-DETR을 실행했으며 모델 로딩 포함 약 31.8초, 워밍업 전 검사 파이프라인 약 1.67초였다. 이는 순수 추론 벤치마크나 산업용 즉시 검출 성능이 아니다. 모델 상시 적재·워밍업·연속 입력·GPU 공존/선점 성능은 17단계 및 최종 노트북 시험에서 해결할 잔여 항목으로 기록한다.

217개 전체 회귀 시험과 Qt 통합 화면 조작 검증을 통과했다. UI 검증은 합성 판정, 새 프레임 ID, OFF 근거 보존, ON/OFF·재시작 설정, 선택 물체의 정확한 VLM 연결, 모의 집기/정지/복구, 이력 운전 차단, 검사 프로세스 취소, 파일 오류, 실제 GPU 사진 경로를 확인한다. UI 자동 조작의 VLM 응답은 명시적인 mock 백엔드로 검증했고, 일반 앱은 Qwen 백엔드만 사용한다. 실제 Qwen 생성은 09단계 보고서에 따로 남아 있다.

검증 결과: `artifacts/desktop-check/report.json`. 실물 정확도·하드웨어 운전·노트북·설치 패키지는 완료로 표시하지 않는다.

```powershell
.venv\Scripts\python.exe scripts\desktop.py
.venv\Scripts\python.exe scripts\verify_desktop.py --output artifacts\desktop-check\새폴더 --gpu
```
