# 성능 개선 1 — RF-DETR 추론 실행

2026-09-06. Windows RTX 3090, PyTorch 2.9.1+cu128, RF-DETR 1.9.4. 이번 변경은 RF-DETR 실행만 다룬다. 물체 묶음 처리, DINO 정상 비교, VLM 및 TensorRT는 후속 작업이다.

## 적용

- CUDA 기본 실행은 **FP32 JIT 컴파일**로 변경했다. 입력 해상도·학습 가중치·클래스 순서·검출 임계값을 바꾸지 않는다. 배치 크기는 1이며 원본 이미지 크기는 기존 전처리에서 모델 해상도로 변환된다.
- 모델 준비 시 RF-DETR 공식 `inference(compile=True, batch_size=1, dtype=torch.float32)`를 한 번 실행한다. 프레임마다 재컴파일하지 않으며 디스크 가중치는 변경하지 않는다. 추론용 사본 때문에 GPU 상주 메모리는 늘어난다.
- CPU는 기존 standard 경로를 사용한다. 최적화 실패는 모델 준비 오류로 처리하고 검사 시작을 차단한다. 자동으로 다른 정밀도나 경로로 전환하지 않는다.
- API의 `inference_profile`로 `standard`, `fp32_jit`, `fp16`, `fp16_jit`를 명시할 수 있다. FP16은 비교 후보로만 제공하며 운영 기본값이 아니다. 사용자 운영 화면에 검증 없이 정밀도를 바꾸는 버튼은 추가하지 않았다.
- 판정 기준이 실행 방식을 구분하도록 모델 식별 버전은 standard `1.9.4`, 컴파일 `1.9.4+fp32_jit`, FP16 `1.9.4+fp16` 등으로 기록한다. 설치 라이브러리 검증은 여전히 정확히 `1.9.4`를 요구한다.
- 기존 standard 모델로 검증한 판정 기준은 새 컴파일 모델과 일치하지 않으므로 자동 재사용하지 못한다. 품목의 판정 기준 생성도 동일한 모델 식별 함수를 사용한다. 실물 데이터로 컴파일 경로를 검증한 후 기준을 새로 등록해야 한다. 현재 실제 제품 모델·판정 기준은 미등록 상태다.

## 측정 결과

공개 예제 개 사진 1장의 원본/좌우반전/밝기/크기/종횡비/4개 배치 변형 8장과 빈 화면·난수 화면 2장, 총 10입력. 각 입력을 10회씩 섞어 100회 측정했다. 다운로드 실패한 추가 사진은 사용하지 않았다. 입력 출처: https://raw.githubusercontent.com/pytorch/hub/master/images/dog.jpg (SHA-256 `f3f87bb8ab3c26c7ecfd3ac60421d7f32b0503d1d6c5baf8bac42ed93d86351a`). 이 예제 이미지는 출고 자산이 아니다.

| 실행 | 중앙값 | p95 | 추론 중 PyTorch 최대 할당 |
|---|---:|---:|---:|
| 기존 FP32 | 34.68ms | 41.11ms | 183.57MiB |
| FP32 JIT | **21.90ms** | **27.38ms** | 287.15MiB |
| FP16 | 33.61ms | 39.39ms | 227.22MiB |
| FP16 JIT | 23.13ms | 30.08ms | 220.93MiB |
| 기존 FP32 재측정 | 35.88ms | 41.40ms | 183.57MiB |
| 최종 반영 소스 FP32 JIT 재측정 | 22.64ms | 28.11ms | 287.15MiB |

FP32 JIT의 중앙값 지연 감소는 첫 기준 대비 **36.84%**, 속도 비는 **1.58배**다. FP16이 항상 빠르다는 가정은 이 구성에서 확인되지 않았다. 첫 실행과 파일 캐시의 차이가 있으므로 모델 적재 시간의 감소는 최적화 효과로 주장하지 않는다. FP32 JIT의 적재+최적화는 11.97초, 별도 워밍업은 2.56초, 적재/컴파일 중 최대 할당은 651.69MiB였다. 메모리는 단일 RF-DETR 프로세스의 PyTorch 할당량이며 GPU 전체 사용량이 아니다.

최종 사용자 소스에서 별도 100회를 재측정한 결과도 중앙값 22.64ms로, 첫 기준보다 약 **34.7% 단축(1.53배)**되었다. 최적화 전후 5개 비교 실행과 최종 실행을 합쳐 총 600개의 원시 시간 표본을 보존한다. 최종 실행 모델 식별값은 `1.9.4+fp32_jit`이며 `deployed-comparison.json`에서 출력 차이를 다시 확인할 수 있다.

측정 범위는 CPU 전처리, 데이터 전송, 모델 추론, 결과 후처리가 포함된 단일 `predict_rgb` 호출이다. CUDA 완료를 동기화해 시간을 기록했다. 촬영, 추적 안정화, 다른 검사기, DB/이미지 저장, UI, VLM, 로봇은 제외했다. 같은 GPU의 다른 프로그램 자원 사용을 통제한 전용 실험실 시험은 아니다. 기존 17단계 640×480 난수 사진 측정과는 입력이 다르므로 직접 전후 비교하지 않는다.

## 출력 비교와 한계

클래스가 같은 상자를 일대일로 대응시켜 좌표·점수·개수 변화와 임계값 경계 통과를 비교했다. 기준 출력을 정답으로 간주하는 정확도 시험은 아니다.

- 점수 0.4 이상: 기준과 FP32 JIT 모두 12개, 전부 대응. 최대 좌표 차이 **0.0412px**, 최대 점수 차이 **0.00305**, 최소 IoU **0.999748**.
- 점수 0.7 이상: 양쪽 모두 11개, 전부 대응.
- 낮은 점수 0.05 이상: 기준 29개, FP32 JIT 28개. 대응하지 않은 기준 후보 **1개**, 대응 후보 최대 좌표 차이 **5.526px**. 결과가 완전히 동일하다는 보장은 하지 않는다.
- FP16/FP16 JIT도 비교했으며 0.05 경계의 후보 증감과 수치 차이를 원시 보고서에 기록했다.
- 실제 제품의 작은 균열, 미등록 NG, 정상/불량 재현율은 미검증이다. 기존 합성 학습 가중치의 제품·결함 클래스 구조 검사는 실행 호환성 확인이며 실물 검증이 아니다.
- RTX 5070 노트북, 실물 다중 물체, VLM 병행 부하는 아직 이번 최적화로 재측정하지 않았다.

## 검증 도구

`scripts/benchmark_rfdetr.py`에서 `--project-root`, `--images`(로컬 예제 이미지 폴더), `--output`(새 폴더), `--profile`, `--repeats`를 지정한다. 입력/가중치 해시와 원시 시간·검출 출력을 저장한다. 장비에 연결하거나 검사 결과를 운영 DB에 등록하지 않는다. 동일 운영 폴더의 GPU 협조 잠금을 사용한다.

`scripts/compare_rfdetr_runs.py`는 `--baseline`, `--candidate`(한 개 이상), `--output`을 받는다. 입력 출처·크기·가중치·수집 임계값·GPU·소프트웨어가 같은 완료 보고서만 비교한다. 출력 차이 판정과 속도 비율을 보존한다.

`scripts/verify_rfdetr_optimization.py`는 기존 합성 학습 확인 폴더를 받아 제품/결함 클래스 순서, 추가 예약 슬롯, 모델 식별 구분, 가중치 원본 보존과 서로 다른 입력 크기의 컴파일 실행을 검사한다. 학습이나 운영 품목 등록을 수행하지 않는다.

측정·검증 자료: `artifacts/inference-optimization/step1`. 각 실행의 `report.json`, `samples.csv`, `comparison.json`, `custom-heads.json`, `all-tests.log`를 보존한다. 설치 배포는 기존 계획대로 현장 검증 후 진행한다.
