# Dobot 연결 PC 작업 인계 — 위치 티칭부터 자동 검사·이송까지

작성: 2026-09-17. 코드 확인 기준: `4c0e630` (이 문서 추가 전 최신 커밋).
대상 저장소: `anhyeongmin/MES_Vision`, Python 3.12 / PySide6 데스크톱 프로그램.

## 1. 이번 인계의 목적과 사용자가 요청한 동작

다음 개발과 실물 검증은 **Dobot Magician과 U20CAM-720P가 함께 연결된 컴퓨터**에서 진행한다.
다른 PC에서도 코드 작성은 가능하지만 COM 포트, 현재 위치, 카메라 장착 오프셋, 이동 경로는 연결 PC에서 확인해야 한다.
현재 문서는 인계와 구현 명세다. 아래 티칭 기능이 이미 구현됐다는 뜻이 아니다.

사용자는 숫자 좌표를 일일이 입력하기보다 다음 방식으로 설정하기를 원한다.

1. 사용자가 로봇을 손으로 원하는 위치에 놓는다.
2. 프로그램에서 이름이 있는 **현재 위치 저장** 버튼을 누른다.
3. 프로그램이 로봇에서 실제 현재 X/Y/Z/R을 읽어 저장한다.
4. 홈 자세, 풀뷰 촬영 위치, 작업 범위, 집기 높이, 분류 후 놓을 위치를 이 방식으로 등록한다.
5. 저장과 이동은 별도 버튼이다. **저장 버튼을 누른 것만으로 로봇이 움직이면 안 된다.**

손으로 이동은 장비가 지원하는 티칭/수동 해제 상태에서 한다. 힘으로 관절을 밀도록 안내하지 않는다.
장비의 실제 티칭 방식·해제 버튼·펌웨어 지원 여부를 현장에서 확인한다.
현재 코드에는 토크 해제/복귀 또는 티칭 모드 제어가 없다. 지원을 확인하기 전 임의의 시리얼 명령을 추가하지 않는다.
손으로 옮긴 뒤 현재 위치가 실제 움직임을 따라 갱신되는지 먼저 확인한다.

테스트 통과는 물리 동작·충돌 없는 경로·모델 정확도 검증을 대체하지 않는다.
풀뷰 검사는 잘라서 확대해도 실제 근접 촬영의 세부 픽셀을 얻지 못한다. 두 방식을 비교 중이다.

Dobot 공식 프로그램과 MES Vision이 같은 COM 포트를 동시에 사용하지 않도록 한다.

## 5. 먼저 구현할 화면: 로봇 위치 설정 / 티칭

자동 검사와 분리한 설정 모드로 만든다. 아직 좌표 보정/분류 프로필이 없어도 연결·현재 위치 읽기·초안 저장은 가능해야 한다.
기존 자동 운전의 검증 가드를 느슨하게 하지 않고 별도 티칭 상태/명령 경로를 둔다.

### 화면 구성과 버튼

- 연결 장비/COM, 현재 X/Y/Z/R(mm/degree), 위치를 읽은 시각, 연결/이동/티칭 상태.
- 카메라 실시간 화면과 현재 원본/보정/크롭 크기 표시.
- `[현재 위치를 홈 자세로 저장]`, 별도 `[홈 자세로 이동]`.
- `[현재 위치를 풀뷰 촬영 위치로 저장]`.
- `[작업판 좌하단 저장]`, `[우하단 저장]`, `[우상단 저장]`, `[좌상단 저장]`.
- `[현재 위치를 상세 촬영 높이로 저장]`, `[집기 높이 저장]`, `[이동 높이 저장]`.
- `[OK 놓을 위치 저장]`, `[NG 놓을 위치 저장]`. 보류는 기본 이송하지 않으며 필요 시 별도 목적지.
- 저장 목록: 이름, X/Y/Z/R, 등록 시간, 초안/검증 상태. 덮어쓰기와 삭제를 구분한다.
- `[저장된 위치로 이동]`은 별도 기능이며 첫 구현은 연결·읽기·저장부터 완료한다.

홈 자세는 사용자가 정한 대기·복귀 X/Y/Z/R pose다. 로봇 좌표계를 재설정하는 장비의 Homing 명령과 구분한다.
저장·연결·앱 시작 시 자동으로 홈 이동이나 Homing을 수행하지 않는다.
홈 복귀도 현재 위치와 도구의 물체 보유 상태를 확인하고 검증된 경로로 실행한다.
중단/오류 후 무조건 홈으로 복귀시키지 않으며, 복구 확인 후 별도 이동을 요청하도록 한다.
홈 자세가 바뀌어도 base 원점을 옮기지 않는다. 장비 Homing으로 기준 상태가 달라지면 보정과 준비 상태를 재확인한다.

풀뷰 위치 저장 시 가능하면 같은 시점 카메라 사진과 조건도 함께 보존한다.
사진 저장은 렌즈 보정이나 픽셀→로봇 보정 완료를 의미하지 않는다.
최종 저장에는 버튼 클릭 직후 worker에서 새로 읽은 위치를 사용한다. UI에 남은 예전 숫자나 마지막 명령 목표를 저장하지 않는다.
이동 중/응답 지연/통신 끊김/비정상 수치에는 저장 실패를 명확히 표시한다.
작업판 모서리를 손으로 가리킬 때는 **같은 물리 기준점(툴의 어느 점)**을 사용해야 한다.
카메라 중심을 맞춘 pose와 그리퍼 끝을 맞춘 pose를 같은 종류로 섞지 않는다.

### 작업 범위의 의미

200×200mm 작업판 좌하단을 (0,0)으로 하는 좌표는 사용자 표시용 작업판 좌표다.
Dobot base 좌표는 별개다. 화면 소수점 한 자리 표시와 내부 계산 정밀도를 분리한다.
네 모서리는 작업판의 평면과 사용 영역을 등록하는 출발점이다.
이 점들만으로 Dobot의 기구학적 도달 범위·이동 경로·충돌 가능성이 검증되지는 않는다.
회전된 작업판은 단순 X/Y 최소·최대 사각형으로 확대해서 허용하면 안 된다. 작업판 다각형과 로봇 제한을 함께 확인한다.
자동 허용 영역은 작업판/보정 유효영역/실제 확인한 로봇 도달 영역의 교집합이어야 한다.
Z 상·하한과 R 범위도 별도로 기록한다. 카메라 위치가 닿는 영역과 그리퍼가 집을 수 있는 영역은 다를 수 있다.

### 저장 형식 제안 — 새 스키마, 기존 파일에 바로 주입 금지

`artifacts/operation/robot-teaching/<설치 ID>/<버전>.json`을 원자적으로 저장한다.
장비 식별값, 연결 회차, base/tool/mount/acquisition revision, 품목, pose 이름/역할,
X/Y/Z/R, 단위와 `robot_base_mm_deg`, 측정 시각, 작업판 모서리 순서, 사진 참조,
`draft / verified` 상태, 검증 기록을 포함한다. 연결 회차는 출처이며 재연결 때 새 확인이 필요하다.
원시 pose는 충분한 정밀도로 보존한다. 저장 즉시 기존 프로필의 `validated=True`로 바꾸지 않는다.
검증 후 기존 `MountedCalibration`·`RobotProfile`로 변환하는 단계를 별도로 구현한다.

## 6. 로봇 이동에 연결하기 전에 필요한 좌표 보정

렌즈 왜곡보정만으로 물체의 로봇 XY를 얻을 수 없다. FOV나 작업판 폭만으로 매핑하지 않는다.
실제로 검사에 쓰는 **보정 후 크롭 영상 좌표**와 로봇 좌표 사이의 대응점을 측정한다.
현재 720×720을 사용하면 그 크기의 영상에서 측정한다. 1280×720 기준 맵을 그대로 재사용하지 않는다.
이미 보정된 획득 영상에는 두 번째 렌즈 보정을 적용하지 않는다. 관련 `require`를 유지한다.

현재 구조는 같은 풀뷰 기준점들에 대해 두 맵을 사용한다.

1. capture_map: 물체 위로 카메라 중심을 이동시키는 XY.
2. pick_map: 물체의 집기점으로 그리퍼를 이동시키는 XY.

카메라-그리퍼 오프셋은 실측/검증한다. 단순히 같은 XY에 Z만 바꾸지 않는다.
현재 코드의 `grasp_uv`는 검출 상자 안의 비율점이다. **회전한 물체의 벽을 자동으로 찾아 파지하는 기능이 아니다.**
물체는 2배 확대 출력했고 벽을 집는 계획이다. 실제 벽 위치/방향과 손가락 진입 공간을 확인하는 파지 정책이 필요하다.
Magician의 R 회전과 카메라가 함께 도는지 장착 상태를 확인한다. 장착 설명을 근거로 RPY를 임의로 제어하지 않는다.
작업판 표면 높이와 물체 검사면/집기 높이를 구분한다. 높이가 다른 평면의 보정을 섞으면 XY 오차가 생긴다.

기존 현장 검증 계획은 맵별 계산점 6개 이상과 별도 검증점 4개 이상이다.
네 모서리 티칭은 이 독립 검증을 대신하지 않는다. 실제 필요한 오차 기준은 그리퍼 여유와 결함 크기에 맞춰 결정한다.

## 7. 연결 PC에서 진행할 순서와 완료 기준

| 순서 | 구현·실행 | 완료 기준 |
|---|---|---|
| 1 | 코드 업데이트, 카메라/COM/장비 상태 확인 | 올바른 장비 선택. 시작만으로 위치 이동 없음 |
| 2 | worker를 통한 현재 pose 표시, 수동 티칭 지원 방식 확인 | 손 이동 후 값 갱신. 끊김/오래된 응답을 현재값으로 표시하지 않음 |
| 3 | 티칭 화면과 초안 저장 구현 | 홈·풀뷰·4모서리·높이·놓을 위치 저장, 재실행 후 복원. 저장 시 이동 명령 0개 |
| 4 | 저장 위치로 제한된 시험 이동 | 운영자 입회 하에 낮은 속도로 확인. 직선/관절/PTP 경로와 카메라·케이블 간섭 확인 |
| 5 | 두 좌표 맵 실측 및 독립 오차 확인 | 실제 사용 이미지 크기·검사면·장착·pose와 보정 일치 |
| 6 | 집기 없이 전체→상세 촬영 이동 | 새 풀뷰 회차에서 올바른 물체 위로 이동·정지·새 프레임 촬영 |
| 7 | 한 물체 벽 집기와 지정 위치 놓기 | 그리퍼 열기/닫기뿐 아니라 실제 집기·놓기 확인 |
| 8 | 판정 정책 검증 후 자동 분류 통합 | 검증된 OK/NG만 분류. 보류·불확실 파지·오래된 회차는 이동 제외 |

티칭 중 자동 검사/자동 이동은 차단한다. 티칭 종료 후에는 기존 회차 좌표를 버리고 새로 촬영한다.
현재 자동 운전은 독립 집기 확인 입력을 요구한다. 센서 유무를 확인하고, 없는 상태에서 true를 반환해 통과시키지 않는다.
센서가 없더라도 1~3의 읽기/저장은 별도로 진행 가능하다. 수동 확인 시험이 필요하면 자동 분류와 다른 명시적 모드로 설계한다.
이동 시 통신 끊김/중단/재시작 후 저장한 명령을 자동 재전송하지 않는다.
저장 위치로 가는 경로는 현재 자세에서 검증된 이동 높이를 거쳐 접근하는 방식 등을 실물로 검토한다. 임의 높이를 기본값으로 넣지 않는다.

## 8. 검증할 코드 테스트

기존 테스트를 유지하고 티칭용 테스트를 추가한다.

- 읽기/저장 버튼으로 PTP·그리퍼 명령이 전송되지 않는지.
- 카메라 전용 사용과 로봇 포트 독점 잠금이 충돌하지 않는지.
- 연결 끊김, stale pose, NaN, 저장 실패, 설치 변경 시 거부되는지.
- 티칭 중 자동 검사 차단, 재연결 후 구회차 무효화, 저장/이동 버튼 분리.
- 모서리 순서·퇴화한 영역·영역 밖 목적지·다른 base/tool 식별값 검증.
- 기존 `test_robot`, `test_station_devices`, `test_station`, `test_station_sort`,
  `test_calibration`, `test_uvc_station_flow`, `test_manual_inspection`, `test_overview_inspection` 중 변경 영향 범위 실행.
- 새 실측값 없이 검증된 운전 프로필이 생성되지 않는지.

예시(프로젝트 루트, 가상 장치 테스트):

```powershell
$env:PYTHONPATH="$PWD/src;$PWD/tests"
$env:QT_QPA_PLATFORM="offscreen"
.\.venv\Scripts\python.exe -B -X utf8 -m unittest test_manual_inspection test_overview_inspection -q
```

위 테스트 명령은 로봇 물리 검증 완료를 뜻하지 않는다. GUI 실행 시에는 오프스크린 환경 변수를 제거한다.

## 9. 다른 PC에서 시작하는 방법

앱을 종료하고 이미 setup을 마친 프로젝트 폴더에서:

```powershell
gh repo sync --source anhyeongmin/MES_Vision --branch main
```

모델은 Git 코드와 별도로 기존 setup/Release 자산 복원 경로를 사용한다. 이 문서 때문에 다시 학습할 필요는 없다.
실측 장비 설정/운영 DB/티칭 자료는 해당 설치에 남기며 다른 PC의 좌표를 그대로 검증된 것으로 가져오지 않는다.
동일 카메라라도 장치 경로가 다르면 `SAME_CAMERA_RECONNECT.md`대로 연결 정보를 갱신한다.

> 손으로 배치한 홈 자세·풀뷰 위치·작업판 네 모서리·높이·OK/NG 놓을 위치를 버튼으로 초안 저장하는
