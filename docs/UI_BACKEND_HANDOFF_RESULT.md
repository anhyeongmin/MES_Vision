# UI 인계 백엔드 작업 결과

2026-09-16. `UI_HANDOFF.md` §0·§2.2·§9를 기준으로 작업했다. UI 배치·스타일은 변경하지 않았다.

## 적용한 흐름

`StationWindow`는 `configs/camera/acquisition.json`에 고정된 U20CAM 렌즈 보정 프로필을 사용한다.
USB 획득 모드는 **1280×720 / MJPG / 30fps**이고 검사 영상은 기존 `Rectifier.apply()`로
왜곡 보정한 뒤 중앙 **720×720**으로 자른다. 좌우 280px은 검사 영역에 포함하지 않는다.
이 과정은 카메라 자식 프로세스에서 수행한다. 별도의 UI 표시용 보정은 하지 않는다.

- `get_latest()`는 검사 프레임을, `get_latest_raw()`는 같은 시점의 원본을 반환한다.
- 데이터 수집 녹화는 기존처럼 원본을 저장한다. 학습 전처리에서 보정을 한 번 적용한다.
- 수동 도착 검사는 원본 경로를 받아 자체 보정을 한 번 수행한다.
- 원본과 검사 프레임은 서로 다른 ID를 갖고, 원본 ID·센서 크기·크롭 범위·렌즈 파일 해시를 기록한다.
- 검사 프레임의 `transformations`는 빈 값이다. 새 획득 좌표계를 뜻하며, 별도의
  `acquisition_identity`가 렌즈 프로필과 크롭 정책을 식별한다. 원본 취급으로 몰래 보정을 생략한 것이 아니다.
- 카메라 프로세스·캡처 게이트·저장·검사 워커가 이 정보를 확인하고 보존한다.
- 기존 `require(not ...transformations)` 가드는 유지했고, 새 획득 식별자 검사도 추가했다.
- D405에는 U20CAM 보정을 적용하지 않는다. 보정 프로필과 다른 센서 해상도는 거절한다.

## ROI와 로봇 좌표

센서 해상도 설정은 1280×720로 유지한다. 보정 맵·검사 레시피에는 720×720과
획득 프로필 해시가 붙은 촬영 조건 ID를 사용한다. 기존 로봇 맵을 280px 옮겨 재사용하지 않는다.
새 로봇 맵은 이미 보정된 영상을 대상으로 측정해야 하며, 좌표 변환에 렌즈 왜곡 모델을
다시 적용하려 하면 거절한다. `none_verified` 등록은 물리적 검증 후 운영자가 해야 한다.

다른 좌표계의 기존 ROI는 자동 변환하지 않는다. 현재 메모리의 기본 ROI를 정사각 전체로 바꾸고
검증 기록을 비운다. 장비 설정에서 새 영역을 확인·저장하기 전까지 검사 준비 가드가 이를 거절한다.
기존 ROI와 보정 파일은 원래 저장 기록에 남는다. 예전 고정 카메라 보정 연결은 새 영역 설정에서 해제된다.
전체·상세 레시피에도 획득 식별자를 저장하여 같은 크기의 다른 보정 결과가 섞이지 않게 한다.

## 판정·장비 상태 표시

기존 `VerdictBanner`와 `ContextBar` 훅을 연결했다. 선택한 물체의 기본 판정과
품목·버전·카메라·로봇·모델 준비 상태를 표시한다. 선택 해제/결과 로드 오류 때 이전 판정이 남지 않게 했다.
VLM 갱신은 기본 판정을 바꾸지 않는다. 새 상태 문구는 영어·중국어·태국어 카탈로그에 추가했다.
새 VLM(NG04 접합부·NG05 구멍)의 비동기 연결은 `VLM_REGION_INTEGRATION.md`를 따른다.

## 장비 없이 확인한 내용

- 주입 UVC 프레임으로 실제 카메라 자식 프로세스의 원본/보정 프레임 쌍과 녹화 저장 크기를 검증했다.
- 저장돼 있던 실제 원본 사진 **11장**을 새 획득 경로로 처리한 결과가 이전 수동 검사 이미지와 픽셀 단위로 일치했다.
- 잘못된 렌즈 파일·해상도·획득 식별자·ROI·기존 로봇 맵·중복 렌즈 보정을 거절한다.
- 단위 테스트의 새 측정 맵은 오프셋 없이 목표 좌표를 계산한다. 이 맵은 테스트 임시 폴더에만 존재한다.
- 실제 검사 화면 흐름의 선택 연동·VLM OFF 기본 판정·언어 변경·연결 해제 상태를 확인했다.
- 기존 테스트 기대값은 변경하지 않았다. 상세 실행 로그는 `artifacts/ui-backend-handoff-v1/`에 있다.

전체 57개 테스트 모듈을 실행했다. 최초 56개 모듈이 통과했고, 장비 정보 없이 저장 사진만 검사하는
기존 워커 경로의 호환성 오류 1건을 수정했다. 이후 해당 모듈과 보정·수동·사진·화면 훅을 포함한
**46개 통합 검사 전부 통과**했다. 새 보정 프레임은 장비 정보가 없는 경로에서 거절한다.
단일 프로세스에 Qt 창이 누적되면 스타일 재적용이 느려져, 테스트 모듈별로 프로세스를 분리했다.
검증 요약: `artifacts/ui-backend-handoff-v1/verification-summary.json`.

현재 장비 설정으로 필요한 새 보정 컨텍스트를 읽기 전용으로 출력하려면:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\check_station_acquisition.py
```

카메라·로봇에 연결하지 않으며 장비 설정이나 보정 승인을 저장하지 않는다.

## 실물에서 남은 확인

1. 실제 카메라에서 크롭 영역에 작업판 전체가 들어오는지, 촬영 거리·노출·안정 대기 조건 확인.
2. 720×720 획득 컨텍스트로 촬영 TCP/집기 TCP 맵과 독립 확인점 재측정.
3. ROI·전체/상세 레시피·촬영 지연·검사 품질 기준의 실측 검증 및 등록.
4. 실제 로봇의 이동·정지·집기·이송 시험. 노트북 검증은 사용자가 요청할 때 마지막에 수행.

이번 작업은 추가 학습이나 새로운 독립 정확도 평가가 아니다. 사용 중인 렌즈 파일도
`EXPLORATORY_NOT_APPROVED` 상태이며, 테스트 통과로 물리적 보정 승인을 대신하지 않는다.
