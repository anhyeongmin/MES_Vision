# 17단계 소프트웨어 측정 결과

측정일: 2026-09-06. Windows 개발 PC의 NVIDIA GeForce RTX 3090에서 실행했다. 실제 제품·카메라·로봇·RTX 5070 노트북은 이 측정에 포함하지 않았다. 설치 배포는 현장 검증 후 진행한다.

## 실제 GPU 반복 부하

RF-DETR Small 두 역할, DINOv2 Small, 2,048개 정상 특징 벡터를 가정한 거리 계산, PNG/측정 JSON 저장을 실행했다. 원본은 생성 RGB 640×480, 각 검사 crop은 200×200이다. 일반 사전학습 가중치와 합성 메모리로 실행한 처리 시간이며 제품 검출/불량 정확도는 아니다.

| 한 장면에서 검사할 crop 수 | VLM OFF 중앙값 | VLM OFF p95 | VLM 분석 중 중앙값 | VLM 분석 중 p95 | OFF/ON 표본 수 |
|---|---:|---:|---:|---:|---:|
| 1 | 132 ms | 155 ms | 152 ms | 206 ms | 30 / 38 |
| 4 | 317 ms | 330 ms | 427 ms | 468 ms | 30 / 36 |
| 8 | 599 ms | 610 ms | 757 ms | 838 ms | 30 / 36 |

전체 물체 **검출 호출만** 보면 중앙값은 OFF 약 30~32 ms, VLM 분석 중 약 34~35 ms였다. 새 물체의 결함 검사와 정상 특징 비교는 각 crop마다 추가된다. 따라서 검출 상자를 표시하는 시간과 모든 물체의 판정이 끝나는 시간은 구분해야 한다.

기본 모델 적재·파일 검증·워밍업은 **25.8초**, 반복 검사 중 모델 교체/재적재는 없었다. VLM 적재 중도 기본 검사 부하를 계속 수행했고 별도 표본으로 보존했다. 모델 적재 화면과 준비 완료 후 검사 시간은 같은 지표가 아니다.

실제 Qwen3.5-4B의 구조화 응답 3건은 모두 완료했다. 검사 부하와 병행한 생성 시간은 각각 **17.6 / 16.7 / 16.7초**였다. 이 값에는 최초 Qwen 적재 대기와 큐 대기가 포함되지 않는다. VLM은 참고 설명만 생성했고 기본 검사 원본 해시는 유지됐다. 설명 문장의 의미적 정확도와 한국어 표현 품질이 합격했다는 뜻은 아니다.

이 측정에서 VLM의 백그라운드 실행은 기본 검사 중앙값을 약 **16~35%** 늘렸다. 3090에서 병행 실행은 가능하지만 기본 검사에 비용이 없다거나 노트북에서도 같다고 판단하면 안 된다. 실제 최대 물체 수와 허용 p95를 정한 뒤 ON/OFF를 선택하고, 노트북에서는 메모리 조건과 지연을 다시 확인한다.

시간에 포함: 전체 검출 1회, 지정한 crop 수의 결함 추론/DINO/거리 계산, 부하용 PNG/JSON 쓰기. 시간에서 제외: 실제 촬영, 추적 안정화 대기, 운영 스냅샷 재검증/DB, Qt 표시, 로봇. 파일 쓰기는 OS 캐시를 사용하므로 디스크 영구 저장 완료 시간과 같지 않다. 작은 표본의 p99/최댓값은 최악 응답 보장이 아니다.

원시 결과: [GPU 보고서](../artifacts/performance-check/gpu/report.json), [모든 시간 표본 CSV](../artifacts/performance-check/gpu/samples.csv).

## 연속 운영 계약 시험

실제 시간 **124.2초**, 제공한 프레임 **2,456개**, 시나리오 **25회**를 실행했다. 카메라/모델 출력은 명시적으로 주입했으며 추적·선택 검사·비동기 이미지 저장·SQLite 등록은 기존 운영 코드를 실행했다.

- 새 물체 검사 75건과 선택 재검사 25건, 총 100개 추적 리비전이 예상대로 공개됐다.
- 정지 물체 중복 검사 없음. 검사 중단 중 새 결과 없음. 그대로 재개할 때 중복 없음.
- 재검사한 물체만 주입된 NG로 변경됐고, 제거된 물체의 실행 가능한 판정은 없어졌다.
- 모델 적재 호출 1회, 종료 후 해제 확인, DB 무결성 검사 통과.
- 첫 시나리오 이후 마지막 RSS 증가는 약 1.27 MiB였다. 2분 관찰이며 장시간 메모리 누수 부재/장기 무고장 증거로 사용하지 않는다.
